# PRD：多轮问答（2026-11-08）

> 上游：[下一阶段方案](下一阶段方案_2026-11-08.md) 工作流 B
> 现状：`/api/ask` 每次独立，追问「那辅酶Q10呢」接不上；演练已有会话存储，问答没有。

---

## 1. 问题

培训场景里，学员的提问天然是连续的：

1. 「鱼油怎么吃？」→「**那孕妇能吃吗？**」
2. 「这款鱼油多少钱？」→「**辅酶Q10 呢？**」
3. 「客户说吃了头晕」→「**那要退货吗？**」
4. 「不是这款，是 P002」→ 纠正上一轮的产品。

现在每个问题都从零检索，第二句里的「那」「这款」「它」没有指代对象，
要么答偏（把「那孕妇能吃吗」当成泛问），要么直接拒答。

## 2. 目标

| # | 目标 | 验收 |
|---|---|---|
| G1 | 支持最近 **3 轮**上下文 | 20 组多轮评测 ≥16 通过 |
| G2 | 指代/省略可改写为独立问题 | 改写正确率 ≥80%（20 组） |
| G3 | 产品切换/纠正能继承或替换产品 | 4 组产品切换 ≥3 正确 |
| G4 | 单轮行为不回归 | 100 题答案基线下降 ≤3；禁用/拒答不增 |
| G5 | 会话安全 | 不能跨用户读会话；TTL 30 分钟；最多 200 会话 |

## 3. 非目标

- 长期记忆 / 跨设备续聊（重启丢会话可接受，与演练一致）；
- 多用户共享会话、语音、图片；
- 把完整历史塞进 prompt（会重演 P1-b 的噪声问题）。

## 4. 用户故事

### US-1 追问（同产品）
> 学员：「鱼油每天吃几粒？」→ 助教回答。
> 学员：「那孕妇能吃吗？」→ 系统应理解为「康源牌鱼油软胶囊，孕妇能吃吗？」，
> 而不是泛问「孕妇能不能吃保健品」。

### US-2 产品切换
> 学员：「鱼油多少钱？」→ 学员：「辅酶Q10 呢？」
> 系统应把「辅酶Q10」识别为新主语，不继承鱼油。

### US-3 纠正
> 学员：「P001 的禁忌？」→ 学员：「不是这款，是 P002」
> 系统应替换产品为 P002。

### US-4 省略
> 学员：「客户吃了头晕怎么办？」→ 学员：「那要退货吗？」
> 系统应继承「吃了头晕」的场景，回答退货/上报流程。

## 5. 交互与接口

- `POST /api/ask` 新增可选 `session_id`（不传 = 单轮，行为完全不变）；
- 响应新增 `session_id`、`rewritten_question`、`turn`（便于前端展示与排障）；
- `/api/ask/stream` 同样支持；
- 前端第一版只展示「已结合上文」，不改布局；后续再做多轮气泡。

## 6. 指标

- 多轮通过率（20 组，规则+人工）；
- 改写正确率（人工抽检 20 条）；
- 单轮 100 题答案基线（不降 >3）；
- 额外延迟（改写 P50 ≤1.5s；规则命中时 <50ms）；
- 会话内存上限与淘汰次数。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 改写把原问题改错 | 低置信度时回退原问题；保留 `rewritten_question` 供前端显示 |
| 历史注入增加噪声 | 第一版只改写、不注入历史；低置信度才注入最近 1 轮摘要（≤200 字） |
| 跨用户会话泄露 | session 绑定身份（user_id+role），不匹配直接当新会话 |
| 会话膨胀 | 最多 3 轮、TTL 30min、LRU 200 |
| 改写调 LLM 增加成本/延迟 | 规则优先；LLM 只在规则未命中时调用，2s 超时 |

## 8. 上线与回滚

- 配置 `MULTI_TURN_ENABLED=false` 默认关闭；打开后 `session_id` 才生效；
- 回滚：关配置即回到单轮；已有 session 不影响；
- 第一版只做 API，前端 UI 后置。

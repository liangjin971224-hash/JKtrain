## 1. 一页摘要

知识问答的检索链路（向量/图谱/关键词三路 + RRF 融合）当前存在三个问题：

1. **没有检索级评测**。现有评测（`eval_questions_v3.jsonl` 45 条 + heldout2 12 条）全部是答案级判定（must_include/must_not_include），无法直接度量「该检索到的块有没有被检索到」。
2. **召回余量贴地**。未完成事项清单 #21 记录：评测集仅 36 条（v3 后 45 条）时 R@5 仅超目标 **0.003**——任何噪声都可能击穿达标线。
3. **无 Rerank**。未完成事项清单 #1 记录：首条命中率有 5–10% 提升空间未兑现。

本 PRD 交付四件事：检索级评测集（LLM 辅助标注）、检索评测工具与门禁、Reranker 可选接入、Embedding 微调与上线/回滚闭环。

## 2. 背景与问题量化

| 事实 | 出处 |
|---|---|
| 向量库仅 580 条 chunk（293/117/140/30），数据层扩容无需求，瓶颈在单步检索质量 | `infrastructure/vector/milvus_search_adapter.py` 模块注释 |
| 向量路判空阈值 `MIN_VECTOR_SCORE = 0.50`，依据是当前 bge-m3 的相似度分布 0.55–0.78 | `application/use_cases/retrieve.py:39` |
| 问答延迟 3~8s 中本地检索 <200ms，大头是 LLM API——**本 PRD 不优化延迟** | 部署与使用说明.md 十一节 |
| 现有模型训练管线（4 轮 QLoRA）全部针对行为侧（拒答/红线），检索侧从未训过 | `train/configs/` v1–v4 |
| `miss_log` 表持续收集未命中问题，是天然的检索负例/标注来源 | MySQL 9 表之一 |

## 3. 目标与非目标

### 目标（G）

| # | 目标 | 度量 |
|---|---|---|
| G1 | 建立检索级评测能力 | 评测集 ≥100 条查询，覆盖 4 个 collection、13 种意图、权限组合 |
| G2 | 固化当前检索基线 | R@5 / R@10 / MRR 基线数字入档 `train/eval_runs/`，可复现 |
| G3 | 接入 Reranker 并可一键降级 | 开启后 R@5 相对基线提升 ≥3 个百分点（bge-reranker-v2-m3 零训练） |
| G4 | Embedding 微调后上线 | R@5 ≥ 基线 +5 个百分点，且答案级评测（v3 45 条）不回退 |
| G5 | 全程有回滚 | 任一步失败，10 分钟内回退到上一个可用状态 |

### 非目标（明确不做）

- ❌ 不改「召回为空不调 LLM」红线及其实现位置（领域层拒答逻辑）
- ❌ 不改权限过滤在检索层拼 filter 的设计（FR-050 红灯项）
- ❌ 不动演练状态机（`drill_session.py` 脚本驱动设计），Agent 化是另一条线
- ❌ 不优化问答延迟（瓶颈在 LLM API，与本 PRD 无关）
- ❌ 不做 Milvus/Neo4j 数据层扩容（数据量差 3~4 个数量级）

## 5. 功能需求

### FR-R1 检索评测集（P0）

- 从 Milvus 4 个 collection 导出全部 chunk（含 chunk_id/text/title/section/permission_level）
- LLM（Codex 执行标注工作包）按双策略标注：
  - **策略 B（主力，~70%）**：chunk → 反向生成 2~3 个问题，gold = 该 chunk；禁止照抄原文连续 ≥8 字；口吻遵循 GLOSSARY.md「培训助教」语境
  - **策略 A（补充，~30%）**：现有 45 条评测题 + `miss_log` 真实未命中问题 → 当前模型 Top-30 候选 → LLM 判「相关/部分相关/不相关」
- 质控：双通道交叉（标注模型 × Qwen/DeepSeek 复判，分歧进人工队列）；20% 人工抽检，一致率 <90% 则修 prompt 重标
- 产出：`train/data/retrieval_eval_v1.jsonl`（目标 100~200 条）+ `hard_negatives_v1.jsonl`（策略 A 的副产物，供 FR-R4 用）

### FR-R2 检索评测工具与门禁（P0）

- 脚本批量执行：query → 向量路检索 → 与 gold_chunk_ids 比对 → 输出 R@5 / R@10 / MRR
- 输出 PASS/FAIL 门禁（阈值见 §6 验收标准），结果入档 `train/eval_runs/`
- 只测向量路（三路融合的端到端口径作为附加指标输出，不做门禁）

### FR-R3 Reranker 接入（P0）

- 新增 `RerankPort` + `bge-reranker-v2-m3` 适配器（零训练，直接用现成模型）
- 接入点：RRF 融合之后、LLM 之前；只对向量+关键词两路候选，图谱路（结构化命中）不做 rerank
- 配置开关 `rerank_enabled`，**false 时行为与现状逐字节一致**（一键降级）
- 多跳路径（`query_plan.py`）的子步骤检索同样生效
- 所有现有测试（1255 个）保持通过

### FR-R4 Embedding 微调（P1，依赖 FR-R1/R2）

- 数据：gold 问题-块对（来自 FR-R1）+ 难负例（FR-R1 副产物 + 硬负例挖掘脚本）
- 训练：bge-m3 + LoRA（云端，沿用 `/mnt/workspace` 管线），合并导出完整模型，**维度保持 1024**
- 上线：重建全部 4 个 Milvus collection（新旧向量分布不同，禁止混存）→ `EMBED_MODEL_DIR` 切换 → 三件套回归
- 回归三件套：①检索级评测达标 ②`eval_questions_v3` 答案级不回退 ③1255 测试全绿 + **`MIN_VECTOR_SCORE` 重校准**（阈值随模型分布移动必须重测，见 TDD §4.4）

### FR-R5 持续飞轮（P2）

- `miss_log` 周度人工/半自动标注 → 月度更新 embed_pairs → 月度重训
- 数据攒够后用同一份数据微调 reranker（先零训练拿基线，后微调）

## 6. 验收标准（量化门禁）

| 门禁 | 标准 | 不达标处理 |
|---|---|---|
| 评测集质量 | ≥100 条查询；20% 抽检一致率 ≥90%；heldout2 的 12 条**原样保留**不参与标注 | 补标 |
| Reranker 收益 | `rerank_enabled=true` 时 R@5 ≥ 基线 +3pp | 不合入，保持关闭 |
| Embedding 上线 | R@5 ≥ 基线 +5pp 且答案级评测 must_include 命中率不降 | 不上线，旧模型目录保留 |
| 阈值重校准 | 用新模型重测相关内容相似度分布，`MIN_VECTOR_SCORE` 及注释依据更新 | 禁止跳过直接上线 |
| 回归 | 1255 测试 0 failed | 修复后才可合入 |
| 回滚演练 | 模拟换模型失败 → 10 分钟内恢复 | 演练通过才算阶段 2 完成 |

## 7. 约束与红线

1. **合规红线不动**：召回为空主动拒答、越界拦截（替医生做判断）行为不变；rerank 不得改变「判空→拒答」的语义，只优化排序质量。
2. **权限过滤位置不变**：仍在 Milvus filter 层；rerank 只能对**已通过权限过滤**的候选重排。
3. **密钥不入库**：标注用到的 API Key 走 `train/scripts/00_env.sh` 环境变量。
4. **数据不出域**：chunk 内容均为内部培训资料（含虚构演示产品设定，见 GLOSSARY.md），标注工作包仅在你本机 Codex 内处理，不上传第三方在线服务。
5. **heldout2 不动**：12 条纯人工金标准永不参与任何训练或标注流程。

## 9. 风险

| 风险 | 概率 | 缓解 |
|---|---|---|
| `eval_questions_v3` 的 reference 映射不到 chunk_id（section 字段对不齐） | 中 | 先跑映射脚本验证覆盖率，<60% 转纯生成式标注（策略 B 为主） |
| LLM 生成的问题与原文过近，R@5 虚高 | 高 | ≥8 字连续片段禁止 + 人工抽检 + 策略 A 引入自然问法 |
| 微调后相似度分布移动，拒答行为漂移 | 高 | 阈值重校准是硬门禁（FR-R4） |
| 580 条语料内难负例不足 | 中 | 跨 collection 负例 + miss_log 真实负例 |
| 云端训练环境与本地版本漂移 | 低 | 沿用现有 00_env.sh 固定版本；评测一律在本地跑 |

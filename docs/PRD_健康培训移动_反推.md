## 1. 产品概述

### 1.1 一句话定位

面向连锁健康食品门店的**内部培训系统**：让员工在有依据、有边界、可追溯的前提下，学会「怎么回答客户」「怎么应对施压」「怎么被考核」。

### 1.2 业务背景（从内容资产反推）

内容资产规模说明了真实痛点：

| 资产 | 规模 | 说明 |
|---|---|---|
| 培训文档 | 15 篇 / 约 10.15 万字 | 岗位职责、接待 SOP、产品知识、设备操作、应急处理 |
| 情景案例 | 16 个（含 5 个红线案例） | 客户从「你们有鱼油吗」到「吃了能停降压药吗」的递进施压 |
| 题库 | 140 道（S1 80 + S2 60） | 51% 是 ★★★ 高危题，考的是边界判断而非记忆 |
| 图谱 | 156 节点 / 184 关系 | 20 个产品（15 保健食品 + 5 普通食品）、18 条禁忌 |

痛点归纳为三条：

1. **合规风险高**：保健食品不得宣称疾病治疗、不得替代药物、普通食品不得有任何功能声称。新人靠背话术记不住边界。
2. **培训不可规模化**：案例演练需要老员工扮演客户，16 个案例 × N 个学员无法覆盖。
3. **考核不可信**：人工出卷易重复、评分标准漂移、演练过程无法复盘。

### 1.3 产品目标（可验证）

| 目标 | 度量 | 现状实测 |
|---|---|---|
| 回答有依据，不编造 | 召回为空必须拒答，且不调用 LLM | 已实现（`RetrievalResult.failed` → 拒答模板） |
| 输出合规 | 三条硬约束：禁用表述、普通食品功能声称、法定警示语 | 42 条禁用规则 / 61 个普通食品禁词 / 7 种警示语等价表述 |
| 召回质量 | R@5 ≥ 0.70 | 0.7778（36 条评测集）；P3 阶段口径为 0.833 |
| 演练可规模化 | 客户台词 100% 脚本化，可复现 | 16 个案例全部可发起演练 |
| 考核可追溯 | 题库改动不影响历史试卷 | 题目快照独立表 `exam_paper_question` |
| 权限可管控 | 三类权限（功能/数据/检索） | 白名单矩阵 + 检索层过滤 |

### 1.4 非目标（明确不做）

| 不做 | 依据 |
|---|---|
| 面向消费者的问诊/荐药 | `GLOSSARY.md` 明确避免「诊疗助手」表述 |
| 给演练打分、下「合格/不合格」结论 | `review_drill.py` 刻意不产出 score/verdict，测试守护 |
| 用未命中日志做员工绩效 | FR-047 原文要求；接口刻意不提供按学员聚合 |
| 替代医生做用药/诊断建议 | 护栏六类规则中「疾病治疗」「药物替代」为最高优先级 |
| 模型微调训练平台 | 本次范围外 |

## 2. 用户与角色

| 角色 | 系统标识 | 典型诉求 | 关键约束 |
|---|---|---|---|
| 学员（门店员工） | `trainee` | 问产品/流程、练案例、看自己日报 | 只能检索 public/internal；只能看自己的数据 |
| 主管（店长/带教） | `manager` | 组卷、导出试卷、看全员日报并写评语、看未命中清单、管账号 | 可检索 restricted/confidential；**不能改学员日报正文** |
| 运维/实施 | 无独立角色 | 启动自检、健康检查、数据重建 | 通过脚本与 `/api/health`，不进业务权限体系 |

**角色只有两种**（`Role` 枚举），`data_permission.py` 额外容忍 `head_teacher`/`admin` 视为主管，属于预留而非已开放能力。

## 3. 核心用户旅程

### 3.1 学员：带着问题来，带着依据走

```
登录（工号+密码）
  → 知识问答：输入「在吃阿司匹林能吃鱼油吗」
  → 系统判定意图「禁忌咨询」→ 图谱权重 0.6 → 命中禁忌边
  → 输出：批准功能原文 + 出血风险提示 + 法定警示语
  → 若知识库无依据 → 明确拒答 + 给出下一步建议（找主管/问医生）
```

### 3.2 学员：在压力下练边界

```
选案例 C04「吃了能停降压药吗」（红线案例，标红）
  → 客户开场白来自脚本，逐轮追问 F1–F4（不吃 LLM 自由发挥）
  → 学员逐轮作答，进度「第 2/5 问」
  → 结束评阅 → 四区块摘要卡：基础信息 / 风险提示 / 要素覆盖 / 待人工确认
  → 卡上明确写「不给分数、不下结论」，判定由人做
```

### 3.3 主管：出一份不重复的卷子

```
选阶段 S1、20 题、指定知识点、难度配比
  → 系统排除该学员 30 天内做过的题（question_usage）
  → 覆盖优先组卷 → 难度不足时降级并写 warnings
  → 草稿 → 定稿生效 → 导出「试卷页 / 答案页 / 组卷报告」三段 Markdown
```

## 4. 功能需求

> 编号说明：`FR-037`~`FR-050` 沿用代码注释里的原始编号；其余为反推编号，前缀表示模块。

### 4.1 知识问答（ASK）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-ASK-01 | 支持自然语言提问，单次 1–500 字 | `AskRequest.question` 长度约束 |
| FR-ASK-02 | 三路召回：图谱 / 向量 / 关键词并行 | 单路失败不影响整体，记入 `degraded` |
| FR-ASK-03 | 意图识别决定三路权重 | 13 套权重表；纯规则分类器，零 LLM；LLM 兜底开关默认关 |
| FR-ASK-04 | 产品名从问句中抽取后归一 | 「康源牌鱼油软胶囊」→ P001；长匹配优先 |
| FR-ASK-05 | 召回为空/全部低于阈值必须拒答，**且不调用 LLM** | 向量阈值 0.50；关键词绝对分 14.0 + 相对比例 0.35 |
| FR-ASK-06 | 拒答话术必须给下一步建议 | 换说法 / 找主管 / 问医生 |
| FR-ASK-07 | 回答必须经过输出护栏 | 三项检测全过才放行，任一项失败即拦截 |
| FR-ASK-08 | 拦截后先重试一次，仍失败则给「说明式拒答」 | 重试 1 次；说明里**不复述违规原文** |
| FR-ASK-09 | 支持 SSE 流式，首句 1–2 秒内到达 | 分句缓冲 + 逐句过护栏 + 违规即截断 |
| FR-ASK-10 | 流式不得绕过护栏 | 已 emit 的每一句都过护栏；警示语在流结束后统一判定 |
| FR-ASK-11 | 回答需附引用块与诊断信息 | `cited_chunk_ids`、意图、各路命中数、耗时、是否降级 |
| FR-ASK-12 | 违规句标注：正文安全版 + 标注版分离 | `answer` 为合规正文；`annotation` 含原文，仅前端标红，禁止入日志 |
| FR-ASK-13 | 多意图拆解（并列） | 最多 3 步；「推荐，禁忌」各自独立召回 |
| FR-ASK-14 | 多跳检索（依赖） | 第 2 跳候选集**只来自**第 1 跳；为空则明说无法比价，禁止全库重查 |
| FR-ASK-15 | 比价不调用 LLM | 价格取图谱数字，模板拼句，最后过护栏 |

**关键取舍（已固化）**：单步问题不得退化成多跳（多一次召回 + 一次生成会拉高 P95）；多跳目前不做流式。

### 4.2 情景演练（DRILL）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-DRILL-01 | 案例列表展示 16 个案例，标注类型/难度/红线 | `is_red_line` 前端标红 |
| FR-DRILL-02 | 客户台词必须来自案例脚本，不由 LLM 扮演 | 保证公平、可复现、可申诉 |
| FR-DRILL-03 | 演练为状态机，逐轮推进 | 开场白 1 + 追问 N；越界作答报错，不静默忽略 |
| FR-DRILL-04 | 会话 30 分钟空闲过期，最多 200 个并发会话 | 进程内 LRU + TTL；重启即丢（已接受） |
| FR-DRILL-05 | 评阅为纯确定性流程，不调 LLM | 规则来自案例文档（要素判定 + 违禁正则） |

## 6. 关键业务规则（红线清单）

1. **无依据不作答**：召回为空或全部低于阈值 → 拒答，且不调用 LLM。
2. **护栏是必经节点**：非流式整段过、流式逐句过，没有旁路。
3. **普通食品零功能声称**：类别判定必须走图谱（权威源），判不出类别时只做禁用词检测，不默认成普通食品。
4. **不替代药物、不诊断、不承诺疗效**：六类禁用表述中的前两类权重最高。
5. **演练不给分、不下结论**：只提供依据，判定由人做。
6. **多跳依赖必须传候选集**：候选为空就承认「无法比价」，不许自由检索。
7. **权限在检索层生效**：不做「先查后筛」。
8. **主管不能改学员正文**：只能写评语。
9. **未命中日志不做绩效**：不提供按学员聚合。
10. **拒答话术不复述违规词**。

## 7. 非功能需求

| 类别 | 要求 | 现状 |
|---|---|---|
| 性能 | 问答端到端 P95 ≤ 8s | 实测 6.6s（含 LLM 生成） |
| 性能 | 首 token ≤ 2s（流式） | 实测 0.5–1s（分句缓冲代价） |
| 性能 | 启动 ≤ 20s（含模型预热） | 约 15s；首请求由 17s 降至 3s |
| 可靠性 | 单路召回失败不影响回答 | 已实现降级 |
| 可靠性 | LLM 主备切换对上层透明 | 千问主 / DeepSeek 备，超时 30s，切换前重试 1 次 |
| 安全 | 密码不落明文、不落日志 | bcrypt；审计日志无凭据字段 |
| 安全 | 防账号枚举与时序侧信道 | 统一错误文案 + 假哈希校验 |
| 安全 | 防路径穿越（答卷归档） | 逐段校验分隔符、`..`、盘符后再拼接 |

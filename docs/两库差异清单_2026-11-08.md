## 6. 必须拍板的分叉决策

### D1 案例切片：117 块（主干旧切片）vs 49 块（当前合并版）

- 主干：`08_数据入库/milvus/build_collections.py` 旧逻辑，案例库 117 块。
- 当前：合并 + 附录剥离 → 49 块，并落 `case_chunk_map.json`；BGE-M3 微调与 205 题评测都建立在 49 块上。
- **推荐：49 块**。理由：微调模型与 gold 标注都绑在 49 块上；保 117 需重建四库 + 重映射 gold + 重训重评（约 2-3 天，且收益未验证）。
- 代价：主干侧若有用 117 块做的历史指标，需标注"旧基线，不可直接对比"。

### D2 LLM 后端：主干 4 种 `kind` vs 当前 API-only

- 主干 `llm_endpoints()` 返回 `kind ∈ {http, ollama, local}`，装配层按 kind 分派；当前只构造 `OpenAICompatibleAdapter`（多 `extra_payload`）。
- **推荐：保留主干的多后端框架，生产配置只用 http(Qwen 主 / DeepSeek 备)**。理由：`LanguageModelPort` 已多后端，删掉分支等于丢能力；但本地 3B 当前质量明显低于 Qwen（77/100），不作为生产默认。
- 待确认：`local`/`ollama` 分支是否随包发布（依赖体积 vs 面试演示价值）。

### D3 端口装配

- 结论同 §5：**并集 10 端口**，`assembly.py` 以主干为骨架加 `_sparse` / `_rerank`，`build_test_container` 同步扩展。
- 风险：`build_test_container` 是 1412/1655 两侧测试的共同入口，改错会让两侧测试同时红。

### D4 多轮问答：**两套实现并存**（本次新发现）

| | 主干 `ask_session_store.py` | 当前 `conversation.py` + `query_rewriter.py` |
|---|---|---|
| 机制 | 存「问题 + 答案前 N 字 + 产品 ID + 意图」，`render_history()` **拼进 prompt** | 存 3 轮摘要，**改写问题**后走原链路，不注入历史 |
| 参数 | `history: str` 进 `AnswerQuestionUseCase.execute` | 无 `history`；`rewritten_question` / `turn` / `rewrite_source` |
| 前端 | ✅ 已接（localStorage、`new_conversation`、「新对话」按钮） | ❌ **无 UI** |
| 评测 | 18 个单测，无问答准确率数据 | 20 组 **17/20**、单轮 100 题 75/100 无回归 |
| 开关 | 无开关（按 `session_id` 是否存在生效） | `MULTI_TURN_ENABLED`（`.env` 已 true） |

- **推荐：以当前侧改写方案为准，删主干 `history` 注入，保留主干前端交互与 `new_conversation` 语义**。
- 理由：主干的"历史塞 prompt"正是 P1-b 验证过会稀释当前问题、把答案带偏的做法；当前侧有评测数据。
- 代价：主干 `ask.py` / `deps.py` / `models.py` / `answer_question.py` 四处需改；前端要补 `rewritten_question` 展示（可选）与 `new_conversation` 适配。

### D5 Rerank 契约：`FusedHit` / 内部降级 vs `RankedHit` / 抛错降级（本次新发现）

| | 主干 | 当前 |
|---|---|---|
| 值对象 | `FusedHit(chunk_id, fused_score, ...)` | `RankedHit(chunk_id, rerank_score, original_rank)` |
| 失败语义 | 适配器**内部吞异常**，原样返回前 top_k | 抛 `RerankError`，`RetrieveUseCase` 捕获后降级 |
| 目录 | `infrastructure/search/` | `infrastructure/rerank/` |
| 是否参与判空 | 未明确 | 明确不参与（TDD §4.3） |

- **推荐：取当前侧 `RankedHit` + 抛错降级**。理由：降级决策留在用例层可测、可观测；主干"静默降级"会让"重排挂了"在日志里只剩一行 warning。
- 代价：主干 `scripts/eval_rerank.py` 与 `tests/.../test_rerank_adapter.py` 需改写；`tests/fakes/fake_rerank.py` 沿用当前侧。

### D6 前端基线：主干 1907 行 vs 当前 1147 行（本次新发现）

- 主干 app.js 含：月报页（生成/批量/复核/内容）、**多轮问答 UI**、`history_turns` 展示。
- 当前 app.js 含：知识问答/演练/试卷/日报/未命中页，**无多轮 UI**；且 `index.html` 无「月度报告」tab。
- **推荐：以主干前端为基线，回填当前侧的运维页（`/ops/retrieval` 调试）与多轮字段**。理由：主干前端是超集，反向回填工作量更小。

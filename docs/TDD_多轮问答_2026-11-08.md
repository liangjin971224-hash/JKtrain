# TDD：多轮问答（2026-11-08）

> 上游：PRD_多轮问答_2026-11-08.md
> 原则：**只加「改写 + 会话」两层，不改检索/生成/护栏**；单轮不带 `session_id` 时行为逐字节不变。

---

## 1. 总体结构

```
POST /api/ask (session_id?)
        │
        ├─ 未开启 / 无 session_id ──────────────► AnswerQuestionUseCase（原路径）
        │
        └─ 开启 + 有 session_id
               ├─ ConversationStore.get(session_id, user_key)
               ├─ QueryRewriter.rewrite(question, session)
               │     ├─ 规则命中（<50ms，无 LLM）
               │     └─ 规则未命中 → LLM 改写（2s 超时，失败回退原问题）
               ├─ AnswerQuestionUseCase.execute(rewritten_question)
               └─ store.append(turn) → 响应带 session_id / rewritten_question / turn
```

**不做的事**：不把历史塞进 prompt（第一版），不改 `_build_prompt`，不改检索窗口。
改写后的独立问题走原链路，因此检索/融合/护栏/拒答全部复用。

---

## 2. 数据模型

### 2.1 `ConversationTurn`（`application/services/conversation.py`）

```python
@dataclass(frozen=True)
class ConversationTurn:
    question: str              # 用户原话
    rewritten: str             # 实际检索/生成用的问题
    answer: str                # 合规正文
    cited_chunk_ids: tuple[str, ...]
    product_ids: tuple[str, ...]
    intent: str
    refused: bool
    at: float                  # time.time()
```

### 2.2 `ConversationSession`

```python
@dataclass
class ConversationSession:
    session_id: str
    user_key: str              # user_id + role，跨用户不可读
    turns: list[ConversationTurn]  # 最多 3 轮（FIFO）
    created_at: float
    last_active: float
```

- `max_turns=3`：多轮评测按 3 轮设计；更长的历史收益低、噪声大。
- TTL 30 分钟；每次访问刷新 `last_active`。

### 2.3 `ConversationStore`（内存，复用 `session_store.py` 的 LRU 模式）

- `OrderedDict[session_id, ConversationSession]` + `threading.Lock`；
- 上限 200，淘汰最久未访问；`get(session_id, user_key)` 校验 `user_key`；
- 过期（`now - last_active > 1800`）视为不存在；
- 接口：`get_or_create(session_id, user_key) -> session`、`append(session_id, turn)`、`reset()`；
- 将来换 Redis 只换适配器，不改用例。

## 3. 查询改写（核心）

### 3.1 规则优先（覆盖 80%）

输入：`question` + `session.turns[-1]`（无历史 → 原样返回）。

| 模式 | 例子 | 改写 |
|---|---|---|
| 纯产品切换 | 「辅酶Q10 呢？」 | 用新产品替换上一轮的主语，保留上一轮意图 |
| 指代 + 追问 | 「那孕妇能吃吗？」 | `上一轮产品 + 孕妇能吃吗` |
| 省略主语 | 「一天几次？」 | `上一轮产品 + 一天几次` |
| 纠正 | 「不是这款，是 P002」 | 用 P002 替换上一轮产品 |
| 场景继承 | 「那要退货吗？」 | `上一轮场景 + 要退货吗` |

实现要点：

1. **产品识别**：`_extract_product_candidates`（复用 retrieve.py 的品类词表）+ 图谱
   `resolve_alias`；当前问题命中新产品 → 产品切换，不继承旧产品。
2. **指代词表**：`这/那/它/这款/该产品/这个产品/还有/呢/同样/也`；
   命中且无新产品 → 继承上一轮 `product_ids` / 场景关键词。
3. **场景关键词**：上一轮问题里的「头晕/退货/孕妇/停药…」保留为上下文前缀，
   只拼接**实体**，不拼整句（避免把上一轮问句塞进检索）。
4. 规则改写后必须含至少一个实体（产品名/文号/明确主题），否则判低置信度。

### 3.2 LLM 兜底（规则未命中时）

- Prompt：最近 3 轮 `Q/A` 摘要（每条 ≤80 字）+ 当前问题；
  要求「改写成不依赖上文的独立问题，只输出问题本身」；`temperature=0`，2s 超时。
- 输出清洗：去引号/前缀；长度 4~120；不得含「根据上文」等元话术。
- 失败/超时 → 原问题（单轮行为）。

### 3.3 置信度与回退

- `high`：规则命中且含实体 → 直接用；
- `medium`：LLM 改写且含实体 → 用，但响应标 `rewrite_source="llm"`；
- `low`：LLM 输出无实体/超时 → 原问题，`rewrite_source="none"`。
- 第一版**不注入历史**；低置信度也不注入，避免噪声（P1-b 教训）。

## 4. 接口改动

### 4.1 `AskRequest`（`interfaces/http/schemas/models.py`）

```python
session_id: str | None = Field(default=None, max_length=64)
```

- 未传 → 单轮路径，行为不变；
- 传了但 `MULTI_TURN_ENABLED=false` → 忽略（响应 `multi_turn=False`）。

### 4.2 `AskResponse`

```python
session_id: str | None = None
rewritten_question: str = ""     # 与原问题相同时留空，减少噪声
turn: int = 0                    # 当前是第几轮（1-based）
multi_turn: bool = False
rewrite_source: str = "none"     # rule | llm | none
```

### 4.3 路由（`ask.py`）

- `_build_use_case` 不变；
- 新增 `_resolve_session(request, identity)`：开关/参数/session 校验；
- 非流式与流式**都在调用 uc 之前改写**；流式在 `done` 事件后追加 turn；
- 拒答也追加 turn（下一轮仍可承接场景），但 `answer` 存拒答话术。

---

## 5. 安全

- `user_key = f"{identity.user_id}:{identity.role}"`；`get` 不匹配 → 新建，不泄露旧会话；
- `session_id` 只允许 `[A-Za-z0-9_-]{8,64}`；非法 → 400 或忽略；
- 不把 `annotation.segments`（含违规原文）写入 session；只存 `answer`；
- 日志只记 session_id 后缀与 turn 数，不记问题全文（沿用现有日志纪律）。

---

## 6. 失败与降级

| 故障 | 行为 |
|---|---|
| store 异常 | 记 warning，走单轮；不影响回答 |
| 改写 LLM 超时/异常 | 原问题；`rewrite_source=none` |
| 改写结果为空/无实体 | 原问题 |
| 会话过期 | 新建，turn=1 |
| 多轮关闭 | 忽略 session_id，单轮 |

## 7. 测试

### 7.1 单测

- `tests/test_application/test_conversation_store.py`：TTL、LRU、user_key 不匹配、3 轮截断、线程安全；
- `tests/test_application/test_query_rewriter.py`：产品切换/指代/省略/纠正/无历史/LLM 失败回退（10+ 例）。

### 7.2 接口

- `tests/test_interfaces/test_multi_turn_api.py`：不传 session 行为不变；传 session 两轮；
  跨用户拒绝；开关关闭忽略；流式 done 后落 turn。

### 7.3 多轮评测（`train/scripts/105_multi_turn_eval.py`）

20 组（每组 2~3 轮）：
- 同产品追问 8 组、产品切换 4 组、纠正 3 组、场景继承 5 组；
- 判分：最后一轮答案的 `must_include`/`must_not_include`（人工写 2~3 个要点）+
  改写是否正确（人工抽检）；
- 门禁：**≥16/20**；单轮 100 题答案基线下降 ≤3；禁用/拒答不增。

## 8. 上线与回滚

- `settings.multi_turn_enabled: bool = False`（env `MULTI_TURN_ENABLED`）；
- 打开后仅对带 `session_id` 的请求生效；单轮路径零改动；
- 回滚：设 false；会话内存随进程重启清空；
- 前端第一版只展示 `rewritten_question` 与 `turn`，不做多轮气泡。

---

## 9. 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 把最近 3 轮原文塞进 prompt | P1-b 已证明多喂上下文会掉答案；且 token/延迟上升 |
| 只用 LLM 改写 | 每条多一次调用，成本/延迟；规则能覆盖 80% |
| 在检索层做「历史 query 拼接」 | 检索窗口只有 5，拼接会稀释当前问题 |
| 把 session 存 MySQL | 会话是短生命周期，内存 + TTL 足够；重启丢失可接受 |

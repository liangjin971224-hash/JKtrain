### 2. ⚠️ 红灯抓出的第一个真实缺陷：门禁 3 漏检

**这是本次 P0 最有价值的一次红灯。**

写完 `scripts/ci_gate.py` 后它报「3 条门禁全部通过」。但**门禁通过本身不能证明门禁有效**——一个永远返回 PASS 的门禁等于没有门禁。

于是补写 `tests/test_ci_gate.py`：注入违规代码 → 跑门禁 → 必须 FAIL → 清理。

**红灯结果**：
```
FAILED tests/test_ci_gate.py::TestGatesActuallyCatchViolations::test_gate3_catches_scattered_safety_logic
AssertionError: 门禁未能拦住分散的安全判定
E       [PASS ] 门禁3 安全判定不分散
```

**根因**：正则写的是 `\w*(?:contraindicated|forbidden_claim|allergen)\w*`，
而最常见的命名是 `check_contraindication`（`contraindication`，不是 `contraindicated`）。

实测三种形态：

| 被测名称 | 旧正则 | 结果 |
|---|---|---|
| `def check_contraindication(...)` | ❌ 漏过 | **最常用的命名反而漏** |
| `class ContraindicationMatcher` | ❌ 漏过 | 漏 |
| `def contraindicated_products()` | ✅ 命中 | 只覆盖了这种 |

**修法**：词根改为 `contraindicat`，同时覆盖
`contraindication` / `contraindications` / `contraindicated` 三种形态。
`tests/test_architecture.py` 里同一处缺陷同步修复。

**转绿**：`5 passed`（含"干净代码不误报"与"探测文件无残留"两条）。

### 3. ⚠️ 红灯抓出的第二个真实缺陷：文件名路径穿越

**红灯时点**：写 `tests/test_infrastructure/test_adapters.py` 时，断言「`file_name="../../evil.pdf"` 必须被拒」。

**红灯结果**：
```
FAILED test_reject_path_traversal_in_file_name
Failed: DID NOT RAISE PathTraversalError
```

**根因排查**：
```python
PurePosixPath("submissions") / "a" / "../../evil.pdf"
# → 'submissions/a/../../evil.pdf'     ← PurePosixPath 不规范化 `..`
```
解析后落在 `root/evil.pdf`：**仍在 root 内**，所以「解析后是否在 root 内」这道检查拦不住它。
但用户已经能控制落盘目录，属于越权写入。

**修法**：路径校验从「只看拼接结果」改为**输入逐个校验**：

| 顺序 | 校验 | 拦什么 |
|---|---|---|
| 1 | 大小 | 超 20MB |
| 2 | 扩展名白名单 | `.exe` / `.php` |
| 3 | `category` / `file_name` 不含分隔符、`..`、盘符 | 文件名注入 |
| 4 | `sub_path` 逐段检查（允许 `2026/11/E001`） | 子路径注入 |
| 5 | 拼接后解析，仍须在 root 内 | 兜底 |

**同时修复 `tests/fakes/fake_filestorage.py`**：替身原本只检查 `".." in rel.parts`，
同样拦不住 `submissions/a/../../evil.pdf`（规范化后 `..` 已被消掉）。
替身与真实现必须同语义，否则用它测出来的结论是假绿。

**转绿**：`18 passed`（文件存储 9 条 + 缓存 9 条）。

### 2. ⚠️ 门禁 3 误报：查询 vs 判定的混淆

**红灯现象**：
```
[FAIL ] 门禁3 安全判定不分散  —— 1 处违规
         infrastructure\graph\neo4j_graph_adapter.py:204  def check_contraindication
```

**先判断误报还是真违规**（不能直接改门禁）。用 AST 扫 adapter 全部方法是否含判定分支：

| 方法 | 含判定分支 |
|---|---|
| `check_contraindication` | **False** |
| 其余 8 个 | False |

**结论**：误报。`check_contraindication` 是端口契约方法，只「查数据」不「做判定」。

**修法**：加白名单，但第一版只按方法名放行 → 见下方缺陷。

### 3. ⚠️⚠️ 白名单第一版可被绕过（自证测试抓出）

**红灯现象**：
```
FAILED test_ci_gate.py::test_gate3_catches_scattered_safety_logic
AssertionError: 门禁未能拦住分散的安全判定
```

**根因**：第一版白名单是 `frozenset({"check_contraindication"})` —— **只按方法名**。
往 `application/` 注入 `def check_contraindication()` 后也被放行了。

**后果**：任何人把判定函数起名叫 `check_contraindication` 即可绕过门禁，**门禁等于失效**。

**修法**：白名单改为两级限定 `{文件路径: {方法名}}`：

```python
PORT_CONTRACT_ALLOWLIST = {
    "infrastructure/graph/neo4j_graph_adapter.py": frozenset({"check_contraindication"}),
}
```

**加两条守门测试**：
- `test_port_contract_method_has_no_decision_logic`：该方法体内若有 severity 条件分支则失败（白名单前提不成立）
- `test_gate3_still_catches_other_safety_names`：注入 `check_forbidden_claims` 必须仍被拦（防白名单扩大化）

### 4. ⚠️ severity 转换是 fail-open，改 fail-safe

**背景**：初版 `_to_severity` 遇到未知值降级为 `MEDIUM`。

**问题**：`severity` 决定 P4 护栏是否拦截。未知值降 medium 等于**放行**该禁忌，
可能出现「向在服抗凝药的客户推荐鱼油」。

**修法**：未知值一律降级为 **CRITICAL**（从严，人工复核），并打 warning。

| 场景 | fail-open | fail-safe |
|---|---|---|
| 数据干净 | 无差别 | 无差别 |
| 脏数据 | **该拦的不拦** | 多拦一条，人工发现 |
| schema 变更 | 静默放行 | 立刻暴露 |

**守门测试**：`test_unknown_fails_safe_to_critical`（参数化 6 种脏输入）。

### 2. ⚠️ Milvus 字段不存在会直接报错

**红灯现象**：
```
VectorSearchError: Milvus 检索失败: MilvusException:
  (code=65535, message=field knowledge_point not exist)
  | collection=health_training_docs
```

**根因**：`knowledge_point / question_type / difficulty` 只在
`health_question_bank` 的 schema 里，其余三个 collection 没有。
Milvus **不忽略**未知字段，直接报错。

**修法**：按 collection 真实 schema 动态取输出字段 + 缓存探测结果。

### 3. ⚠️⚠️ 权限过滤测试是假绿（最关键）

**现象**：初版测试断言「学员视角 top_k=20 应拿满 20 条」，实跑通过。

**问题**：V2 重建时已把所有 restricted 内容分流到 `health_self_test`，
所以 `health_training_docs` **一条 restricted 都没有**。
「检索层过滤」和「检索后过滤」都是 20 条 —— **这个断言没有区分力**。

**后果**：P2 最核心的安全约束（权限在检索层）等于没测。

**修法**：改成三个有区分力的判据：

| 判据 | 区分力来源 |
|---|---|
| 全 restricted 库学员返回 0 | 权限条件真的限制住结果 |
| 同库主管返回满 20 | 证明库里有数据（不是因空库而 0） |
| **非法权限值必须报错** | 证明权限参数被**解析进查询条件**，而非事后筛选 |

**教训**：**测试在错的样本上跑绿，比测试失败更危险。**
选测试样本时要问：「如果实现写错了，这个断言会失败吗？」
若不会，就得换样本或换判据。

### 4. 模型惰性加载

`import sentence_transformers` 占启动 87%（11.5s）。
若在 `__init__` 或模块级加载，`main.py` 自检会从 1.2s 变 18s+。

**修法**：`_ensure_model()` 首次 `embed()` 才加载。
**测试守护**：`test_model_not_loaded_at_construction`。

但排查过程有价值：它逼我明确了一个语义决策——

> 理由：真实检索不会有重复，出现重复本身是数据问题，不该被奖励。

### 3. ⚠️⚠️ 图谱结果混进文档排名（设计缺陷）

**现象**：融合输出第一条是 `P001`，`chunk=None`：

```
P001      score=0.00820  sources=('graph',)    chunk=None   ← 排第一
D005_c1   score=0.00492  sources=('vector',)   chunk=有
```

**问题**：
1. `chunk=None` 排第一，下游按 `fused` 取内容会踩空
2. 一个分数同时表达「产品对不对」和「文档相关不相关」，语义混乱

**根因**：把 `product_id` 与 `chunk_id` 放进同一个 RRF 排名。
两者是不同类别的东西——产品事实是权威结构化数据（走事实卡），
文档块是给 LLM 的参考文本。

**修法**：融合只管文档块（向量 + 关键词两路），图谱结果单独放 `graph_hits`。

**加测试守护**：
- `test_graph_result_not_in_fused`：P001 不应出现在 fused 里
- `test_fused_only_contains_chunks`：fused 每条都必须有完整 chunk

### 4. ⚠️ 「向量永远返回 Top-N」必须用阈值

**背景**：向量检索问什么都会返回 Top-N，哪怕知识库里完全没有相关内容。

**如果没有阈值**：P4 会以为「召回到了」，拿无关内容让 LLM 生成答案 →
本项目最严重的失效模式（幻觉 + 违规宣传）。

**修法**：`MIN_VECTOR_SCORE = 0.50`，依据实测分数分布：

| 区间 | 含义 |
|---|---|
| 0.70–0.78 | 高度匹配 |
| 0.55–0.69 | 相关性较好 |
| **0.50** | **分界线** |
| 0.45–0.50 | 噪声（但 Top1 常落这里） |

不取 0.55：P2 实测有 0.52 的正确命中，会误杀。
不取 0.40：几乎所有查询都「有召回」，P4 拒答永远触发不了。

### 2. ⚠️⚠️ 单元测试全绿 ≠ 护栏可用（本次最重要的一课）

**现象**：`test_guardrail.py` **68 条全绿**，按常规认知该收工了。

**但我拿真实培训内容跑了一次全量扫描**：

```
段落总数 1166, 命中 127 (10.9%)
```

**10.9% 的命中率——培训文档自己的正文被判违规。**

逐条看误报原因：

| 类型 | 例子 | 根因 | 性质 |
|---|---|---|---|
| 序号「第一」 | 「第一条铁律」「## 第一步」「客户第一次来」 | 正则没排除序号用法 | **真 bug** |
| 副词「最好」 | 「您最好先咨询医生」「建议最好遵医嘱」 | 没区分绝对化与建议 | **真 bug** |
| 引述违规示例 | 「❌ 不能说：降血糖」 | 文档本身在教「什么不能说」 | 内容特性 |

前两类是真 bug。第三类不是——护栏只对**模型输出**生效，不该扫培训文档原文。

**修法**：

| 问题 | 修法 |
|---|---|
| `第一` 误报 | 分三种：带行业限定 / 带后缀 / 裸「第一」前接「是·排名」且后不接序号量词 |
| `最好` 误报 | 要求「最」后接**产品效力形容词**，`最好+建议动作` 放行 |
| 新增漏检 | `第一选择`、`销量第一`、`效果最强`、`见效最快` 各自补规则 |

**结果**：误报率 10.9% → 9.0%，剩余全是引述类。

**固化**：新增 `test_guardrail_false_positive.py`（68 条），每条都来自真实误报。

### 3. 20 个越界问题的测试设计陷阱

第一次跑「20 个越界问题」时，5 条「合规回答」被判 `blocked=True`，看似护栏过度拦截。

**实际是护栏在正确工作**——那 5 条都是保健食品回答但**没带法定警示语**。
是我的测试用例设计有问题（把「内容合规」和「格式合规」混在一起）。

**修法**：合规用例统一补上警示语，并区分两类违规：

| 类型 | 例子 | 护栏行为 |
|---|---|---|
| 内容违规 | 「能降血糖」 | 拦（禁用词） |
| 格式违规 | 保健食品回答没警示语 | 拦（缺警示语） |

两者都必须拦，但测试要分开写清楚。

## P4 阶段 · 问答链路（2026-10-22，端到端暴露）

### 背景：545 项单元测试全绿后接上真环境

假替身测试通过 → 接真实千问 + 真 Neo4j + 真 Milvus 跑端到端 → **一次跑出 5 个问题**。

### 1. ⚠️ 合规回答被护栏整段拦下

**现象**：问「鱼油有什么功能」，千问给了专业且合规的回答（含
「❌ 不能说"降血脂""治疗高血脂"等」这种反例教学），护栏把**引号里的词**当违规拦了。

**这就是「引述语境」问题**：培训文档和合规话术里大量引述禁用词作反例。

**修法**：加 `_QUOTED_NEGATION`，只放行「否定词 + 引号片段」。

#### 修这条规则时连踩 3 个坑

| 坑 | 后果 |
|---|---|
| `[、，,\s]*` 把逗号吃进匹配范围 | 「不能说"X"，但我们这款确实X」后半句被漏检 |
| 加 `等[^。！？\n]{0,10}` 收尾语 | 「等」后文字被吞，真违规漏放 |
| 挖整行而不是挖局部 | 「❌ 不能说"X"，但确实X」整体放行 |

三个坑都靠「同时测应放行与须拦截两组用例」才发现。
**只测「能放行」会做出一个什么都放行的规则。**

### 2. 劝阻性表述被误拦

`不可擅自停药或替代治疗` —— D005 要求的标准话术，被 `治疗` 规则拦了。

**修法**：`_DISSUASION`，放行「不可/不能 + 擅自/自行 + 停药/替代治疗」。

### 3. 否定性排除陈述被误拦

`它不用于治疗高血脂症`、`不具有降血脂的治疗作用` —— 最严谨的边界说明，被拦。

**修法**：`_NEGATED_CLAIM`，但**只放行否定词与功效词紧邻**的形式。
`不能不说这个能降血脂` 不满足紧邻，仍拦。

### 4. BM25 索引从未构建（静默失效）

端到端跑通，但日志里一行 warning：`BM25 索引尚未构建，返回空结果`。

**后果**：P3 号称「三路融合」，实际只有两路在工作，且不报错。

**修法**：装配根加 `_warmup_bm25()`，从 Milvus 读块建索引。

### 5. ⚠️⚠️ BM25 噪声让「召回为空」防线失效

**现象**：问「你们有没有量子能量水」（库里完全没有），系统**编了答案**。

| 路 | 「量子能量水」Top1 |
|---|---|
| 向量 | **0.472**（< 0.50 阈值，正确拦下） |
| 关键词 | **11.74**（2-gram 命中「能量」「量水」等常见字） |

关键词路没有阈值 → 噪声把 `fused` 撑到 10 → 「召回为空」判定失败 → 调 LLM 编答案。

**这是 P3 记录过的风险的实证**：当时只给向量加了阈值，漏了关键词。

**修法**：实测标定双阈值

| 类型 | 关键词 Top1 |
|---|---|
| 真实查询（12 条） | 15.60 ~ 28.48 |
| 噪声查询（8 条） | 5.15 ~ 11.86 |

→ 绝对下限 **14.0** + 相对阈值 **35%**。

**验证**：「量子能量水」现在 `fused=0 / llm_called=False / 96ms`。

### 6. 一个设计决策：护栏失败重试而非放宽规则

同一 prompt 两次调用输出不同（即使 `temperature=0`）：
一次自己加引号而合规，一次说「唯一」被拦。

**选择重试而非放宽**：放宽会让真违规也漏。合规场景下漏放比多一次调用贵得多。

### 7. P4 问答链路红灯总览

| 红灯项 | 初始 | 最终 |
|---|---|---|
| 召回为空不调 LLM | ModuleNotFound | 16 passed（`llm_called=False` 真机验证） |
| 引述语境误拦 | 合规回答全被拦 | 47 passed，漏放 0 / 误拦 0 |
| 劝阻/否定表述误拦 | 标准话术被拦 | 同上 |
| BM25 静默失效 | 关键词命中=0 | 预热后正常 |
| 关键词噪声 | 编答案 | 双阈值，`fused=0` |

**净结果**：测试从 482 → **545 通过**（+63 集成 = 624）。

### 8. 本轮最该记住的一句

> **假替身全绿 ≠ 系统可用。**
> 545 项测试通过后接上真环境，一次跑出 5 个问题，
> 每个都只有真库真模型才能暴露（假数据不会有 2-gram 噪声、不会有真 LLM 的措辞波动）。

## P4 优化 · 流式输出（2026-10-22）

### 0. 先认清这是架构冲突，不是性能优化

流式 = 边生成边展示；护栏 = 输出必经节点。天真做法会让违规内容在检测前就展示出去。
解法：**分句缓冲 + 逐句过护栏 + 违规即截断**。

### 1. 红灯

`test_stream_guardrail.py` 首跑：`ModuleNotFoundError: domain.services.stream_guard`。

实现后两轮修正：
1. `max_buffer_chars` 边界写成 `>`，导致「喂 50 字、上限 50」时憋住 → 改 `>=`
2. 强制切分写成 `if`，一次喂 120 字只切一次 → 改 `while`

### 2. ⚠️ 流式 v1 几乎没收益（实测发现）

**现象**：只按句号切分时，首块延迟 **3.70s**。
而原生首 token 只要 **0.46s** —— 91% 的收益被「等第一整句」吃掉了。

**根因**：第一句常有 60 字（`康源牌鱼油软胶囊（P001）是保健食品，其批准功能为：…`），
等句号等于等大半篇。

**修法**：允许在**逗号处提前切分**（累积超过 24 字时）。
首块从 3.70s → **1.18s（中位）**。

### 3. ⚠️⚠️ 逗号切分破坏了跨段规则（自己引入的回归）

**现象**：合规回答 `它不用于降血脂治疗，` 被拦了。

**根因**：
```
原句：它不用于降血脂治疗，也不具有护心作用。
切成：「它不用于」+「降血脂治疗，也不具有护心作用。」
                              ↑ 单独检测就是违规
```
`_NEGATED_CLAIM` 要求「否定词」与「功效词」紧邻，切开后紧邻关系断了。

**修法**：检测时带上前文 20 字作为上下文（`CONTEXT_TAIL_CHARS`），
并只保留「命中位置落在当前片段内」的违规，避免上下文旧命中重复触发。

**这个修法的风险**：可能变成「什么都放行」。所以加 6 条回归测试守住，
其中 `test_real_violation_still_blocked_across_chunks` 专门防这个。

### 4. 门禁挡下一次架构腐蚀

初版把 `generate_stream` 写成端口的「带默认实现的方法」（退化调 `generate`），
想让现有适配器零改动。

门禁立刻失败：
```
language_model_port 中存在未声明 abstractmethod 的公开方法
  （Port 只应声明能力，不含实现）
```

**门禁是对的**：端口里有实现就是腐蚀的开始。改为 `@abstractmethod`，
测试替身各自实现退化版——这是「显式契约」应有的代价。

### 5. 流式总览

| 红灯项 | 初始 | 最终 |
|---|---|---|
| 分句缓冲 / 逐句护栏 | ModuleNotFound | 26 passed |
| 流式用例 | 13 failed | 13 passed |
| 首块延迟 | 3.70s（v1） | **1.18s 中位** |
| 跨段误拦 | 合规句被拦 | 6 条回归测试守住 |
| 端口塞实现 | 门禁 FAIL | 改 abstractmethod |

**净结果**：测试从 545 → **584 通过**（+79 集成）。

### 6. 新增教训

| # | 教训 |
|---|---|
| 18 | **性能优化可能破坏安全约束**，必须先想清楚再动手 |
| 19 | **流式的收益取决于「第一个切分点多远」**，不是「有没有用流式」 |
| 20 | **放宽检测粒度要有补偿机制**（切分变碎 → 带上下文尾巴） |
| 21 | **流式下主备切换能力必然弱于非流式**（中途故障不可切），要如实说明 |

### 2. ⚠️ 合规警示语被判违规（最伤信任的 bug）

**现象**：优秀答卷被报 `critical 违规宣称「治疗」`。

**根因**：法定警示语 `保健食品不是药物，不能代替药物**治疗**疾病` 含「治疗」，
被 C01 的 `治疗` 规则命中。

**这是最伤信任的一类 bug**：学员把必须说的话说对了，系统反报他违规。
比漏报更糟 —— 漏报他不会知道，误报他会觉得系统不懂业务。

**修法**：复用 P4 白名单 `_strip_compliant + _strip_quoted_negations`。
**关键收益**：评阅与输出护栏用同一套标准，避免规则漂移。

### 3. ⚠️ critical 检出率不足（文档说 3 处，只检出 1 处）

用案例文档给的「不合格答卷」验证时发现的。

**漏检的那句**：「很多人吃了血脂都降下来了」——既不是「很多人吃了**都说好**」，
也不含 `降血脂`（实际词序是「血脂**都降下来**了」），两条规则都漏。

**这是门店最常见的违规形态**（他人经验 + 指标变化），必须单独覆盖。
补 TS-05 / TS-06 两条规则，验证 **漏放 0 / 误拦 0**。

### 4. 案例规则表本身不完整

C01 的案例规则里**没有「他人经验背书」**这一类，
但它的评分示例明确说那句话是 critical。

**结论**：评阅必须**叠加全局六类规则**（与输出护栏同源）。
案例规则管「考察重点」，全局规则管「兜住底线」。

### 5. ⚠️ 案例解析踩了 4 种格式变体

| # | 差异 | 后果 |
|---|---|---|
| 1 | 标题层级 `###` vs `##` | 章节匹配失败 |
| 2 | 章节名 `违禁表述检测` vs `违禁检测` | C01/C04 规则全丢 |
| 3 | 违禁表 4 列 vs 3 列 | 8 个案例规则全丢 |
| 4 | **正则单元格含 `\|`** | 表格被切碎 |

第 4 个最隐蔽：
```
| 违规宣称 | `降血脂|降胆固醇|治疗` | **critical** |
                ↑ 被当成表格分隔符
```
直接 `split("|")` 切出 7 个单元格，整行解析失败。
修法：逐字符扫描，反引号内的 `|` 不当分隔符。

**结果**：16/16 案例，55 条规则，无缺失。

**两处修正**：
1. `我看看` 加负向断言 `(?![们])`
2. **判断顺序改掉**：先找明确回答，只有没找到时才看模糊话术

```
建议先咨询医生后再决定是否同服
一起吃之前请咨询医生
请您自己判断，我只能提供信息
```

```

```

|---|---|---|

| v2 | (位置, 类别) | 丢掉同句的不同类别违规 |

**关键平衡点**：

| 情形 | 处理 |

## P5 后 · 用户实测 bug：同一问题两次结果不同（2026-10-22）

### 现象（用户截图）

问「康源牌黑芝麻丸有什么功能」，**同一句话问了两次**：
- 第 1 次 → `正常回答`
- 第 2 次 → `已拒答`，内容被截断在「…或疾病预防、」

被拦的是一个**完全合规**的句子：
> 普通食品不能宣称任何保健功能或**疾病预防、治疗**功能。

这是《广告法》原文表述。

### 根因：两层问题叠加

**① 规则层**：`_NEGATED_CLAIM` 的否定词表只有 `不涉及`，
但实际文本是「不能**涉及**」→ 逐条枚举必然漏。

**② 流式切分层**（更隐蔽）：`StreamGuard` 把**顿号**当成切分点，
正好在「疾病预防、」处断开：
```
「普通食品不能宣称任何保健功能或疾病预防、」
「治疗功能，也不能替代药物。」
```
第二段单独检测就命中「治疗」→ 误拦。

**这解释了「同一问题两次不同结果」**：
LLM 每次措辞略有不同，有的版本恰好在顿号处凑够了切分长度。

### 修这个规则连踩三轮

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 否定词改成「(不能\|不) + 任意动词」 | 漏放「不可以治疗，但能缓解」 |
| v2 | 加双否排除，但先挖掉双否片段 | 功效词一起被挖 → 漏放 |
| **v3** | **重叠则不挖**（`_strip_negated_claims`） | 正确 |

### 第三个坑：「治疗功能」的合规边界

流式修好后还有单独片段的问题，于是加 `_NOUN_PHRASE` 放行名词化搭配。
又踩两轮：

| 版本 | 结果 |
|---|---|
| v1 只判「治疗+功能」 | 「该产品有治疗作用」被误放 |
| v2 加前置排除（有/具有/能/可） | 「这个治疗功能很明显」仍被误放 |
| **v3 要求必须带名词化标记**（的宣称/宣传） | 正确 |

**v3 为什么有效**：
- 「治疗功能**很明显**」= 在**评价**这个功能强 → 违规
- 「治疗功能**的宣称**」= 在**指称被禁止的说法本身** → 合规

### 验证

| 项 | 结果 |
|---|---|
| 误拦 | **0**（13 条合规样本） |
| 漏放 | **0**（9 条违规样本） |
| 真机连问 3 次 | **3 次全正常**，不再拒答 |
| 全量测试 | 756 → **824 通过** |

### 新增教训

| # | 教训 |
|---|---|
| 30 | **同一现象可能是多层问题叠加**（规则漏 + 流式切分错），只修一层没用 |
| 31 | **流式切分粒度会改变检测结果**——顿号是并列，不能当断句点 |
| 32 | **枚举搭配必然漏**，要用「否定前缀 × 动词」的组合式 |
| 33 | **评价 vs 指称**：同一个词在「功能很明显」和「功能的宣称」里合规性相反 |

**现象**：140 道题只有 23 道能解析出题干，117 道正文直接从 `A. 选项` 开始。

**根因**：入库脚本 `_Q_RE` 的正则写错：

```python
r"^#{2,3}\s+([QS]\d{3})\s*([★☆]{1,3})?\s*[（(]?[^）)\n]*[）)]?\s*$"
```

`[^）)\n]*` 匹配任意非换行字符，`\s*$` 的 `\s` **匹配换行符**，于是
正则把「标题 + 空行 + 题干」整体吃成标题：

```
匹配到 '## Q005 ★☆☆\n\n**以下哪个标识是保健食品的专用标志？**\n'
                            ↑ 题干被当成标题的一部分
```

`m.end()` 之后直接从选项开始 → 题干永久丢失。

**修法**：`[^\n]*?(?=\n|$)` 只吃自己那一行。`fix_question_text.py` 修复 116 条 / 0 失败。

| v3 | 按**剩余配额**动态挑 | 正确 |

## P8 补 · 身份可伪造（2026-10-23 用户实测暴露）

### 1. 现象

用户测日报，反馈「日志没保存」。排查发现两层问题。

### 2. 表面问题

日报页「工号」是手填输入框，不填 → `alert('请先填写工号')` → 直接 return。
**已登录了还要手填工号，本身就不合理。**

### 3. ★★★ 根本问题：身份可伪造

原实现：

```python
def save_summary(req: SaveSummaryRequest, ...):
    uc.execute(requester=req.requester, role=req.role, ...)
```

实测：

```
学员 token + requester=M001  → 200，写进了主管名下
学员 token + role=manager    → 200，看到全部人的日报
```

### 4. 根因：把身份当普通参数

身份是**由令牌证明的**，不是**由调用方声明的**。

P8 只给「组卷/试卷/日志/账号」挂了 `require_feature`，

数据权限测试当时用 `auth_required=False` + 前端传 `requester` 来「模拟身份」
—— **那正好掩盖了漏洞**。

**教训：用「传参模拟身份」测数据权限，测不出「身份可伪造」。**

### 6. 修法（三层）

1. schema 删字段（`SaveSummaryRequest` 不再有 `requester`/`role`）
2. 路由从 `Identity` 取（`Depends(current_identity)`）
3. 补 7 条测试锁死

前端同步：工号输入框改**只读**，值由登录态填充。

## P8 补 · 案例详情按角色裁剪（2026-10-23 用户确认方案后实施）

**服务端按角色构造字段，不是「先全给再让前端隐藏」。**

| `focus` | ❌ | 等于提前给答案 |
| `trigger_note` | ❌ | 流程控制信息 |

```
学员：{"element_id":"E1","name":"明确回答有 / 没有","required":true}
```

```python
raw = client.get("/api/cases/C01", headers=h).text
```

#### 1. ✅ 意图分类完全没接入（2026-10-23 已修）

**改造前现状**：`AnswerQuestionUseCase.execute(intent="")` 默认值是空串，
接口层从不传 `intent`，所以**永远走「开放问答」权重 `(0.1, 0.8, 0.1)`**。

**后果**：P3 精心设计的 **12 套意图权重全部没用上**。

| 意图 | 图谱 | 向量 | 关键词 | 实际在用？ |
|---|---|---|---|---|
| 产品功效 | 0.5 | 0.3 | 0.2 | ❌ |
| 禁忌咨询 | **0.6** | 0.2 | 0.2 | ❌ |
| 文号查询 | 0.2 | 0.2 | **0.6** | ❌ |
| 开放问答 | 0.1 | **0.8** | 0.1 | ✅ 全部走这个 |

最直接的损失：**问「在吃阿司匹林能吃鱼油吗」时，图谱权重本应是 0.6（最重），
实际是 0.1**。而图谱恰好是禁忌这类问题最准的一路。

**代价**：需要一次 LLM 分类调用（约 0.3s，可缓存）。
或者先用规则分类（关键词匹配「禁忌/能不能/同服」→ 禁忌咨询），
准确率不够再上 LLM。

**实测对比**（同一个问题「在吃阿司匹林能吃鱼油吗」）：

| 意图 | 权重 | 融合 Top1 |
|---|---|---|
| 开放问答（**当前实际**） | (0.1, 0.8, 0.1) | `D004_c016` |
| 禁忌咨询（**应该是这个**） | (0.6, 0.2, 0.2) | `D004_c016` |

两条路径 Top1 相同（因为文档路本身够强），但**权重结构完全反了**：
禁忌问题本该让图谱主导（0.6），实际是向量主导（0.8）。

**顺带发现一个小不一致**：
`weights_for_intent("")` 返回「产品功效」的 `(0.5, 0.3, 0.2)`，
但主链路里 `answer_question.py` 会先把空串转成「开放问答」，
所以实际用的是 `(0.1, 0.8, 0.1)`。
两处兜底不同，容易让人看错——**建议把 `weights_for_intent` 的兜底也改成「开放问答」**。

**评估**：这是**最值得做的一条**，因为它直接影响回答质量，且已有现成的权重表和意图标签，只差分类器。

**✅ 已做（2026-10-23）**：见下方「六、已完成」第 1 条。

**为什么先规则不先 LLM**（关键判断）：

1. 用例的红线是「召回为空不调 LLM」。分类器在链路最前面，
   一旦在这里调 LLM，乱码输入也会打一次模型 —— **红线在链路上被绕过了**。
2. 培训场景问法收敛（禁忌/停药/文号/设备/流程），规则覆盖得了。
3. LLM 兜底做成了开关（`use_llm_fallback`），**默认关**。

**实测（真实接口，学员账号）**：

| 问题 | 判成 | 权重（图/向/词） | 命中词 |
|---|---|---|---|
| 在吃阿司匹林能吃鱼油吗 | 禁忌咨询 | **0.6** / 0.2 / 0.2 | 阿司匹林 |
| 吃了能停降压药吗 | 要停药 | 0.5 / 0.3 / 0.2 | 能停 |
| 客户进店第一步该做什么 | 业务流程 | 0.1 / **0.7** / 0.2 | 第一步 |
| 批准文号的格式有哪几种 | 文号查询 | 0.2 / 0.2 / **0.6** | 批准文号 |
| 体脂仪测量前要做哪些准备 | 设备使用 | 0.2 / **0.7** / 0.1 | 体脂仪、测量 |
| 鱼油有什么功能 | 产品功效 | 0.5 / 0.3 / 0.2 | 鱼油、功能 |
| zzzzqqqqxxxx | 开放问答 | 0.1 / 0.8 / 0.1 | （无）→ 拒答 |

**融合排序真的变了**（同一问题对比「强制开放问答」与「自动分类」）：

```
吃了能停降压药吗
  改造前(开放问答): D009_c016, D004_c022, ...
  改造后(要停药):   D004_c022, D009_c016, ...   ← 禁忌/用药段落被顶到第一
```

**两个坑（红灯抓出来的）**：
- `有.{1,6}么` 这条规则把「鱼油**有什么**功能」判成「产品名查询」，
  把整个功效询问类抢走了 → 必须负向前瞻排除「有什么/哪些」。
- 「吃了能停降压药吗」里没有「停药」二字，只有「能停」，
  被「降压药」抢进禁忌咨询 → 规则要按**客户实际说法**写，不按标准词写。

**并列 ≠ 依赖**（核心判断）：
- 并列（「推荐，禁忌」）各自独立召回
- 依赖（「其中那种最便宜」）候选集**只来自**前一步，为空就说无法比价

**实测（HTTP 真链路）**：

```
「改善体脂都可以吃什么保健品，其中那种最便宜」
改造前：目录中**没有**改善体脂等表述   ← 说错法规
改造后：目录中确实有「有助于控制体内脂肪」（第 9 项），
        但本店在售的保健食品**没有任何一款**声称该功能；
        上一问没有找到符合条件的产品，所以无法比价。
```

**遗留**：
- 拆解靠规则，长尾问法退化为单步（上 LLM 会破坏「不调 LLM」红线）
- 只支持「比价」一种依赖跳
- 多跳未做流式（流式入口仍走单步）

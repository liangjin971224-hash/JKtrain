## 3. ⚠️ 端到端跑出 5 个真实问题（本阶段主要工作量）

假替身测试全绿（545 项），但接上真实千问 + 真库后，暴露出 5 个只有真环境才能发现的问题。

### 问题 1：合规回答被护栏整段拦下（最严重）

**现象**：问「鱼油有什么功能」，千问给了**很专业且合规**的回答：

```
康源牌鱼油软胶囊是保健食品，其批准功能为：
「有助于维持血脂（胆固醇/甘油三酯）健康水平」。
需要特别说明：
✅ 这是国家市场监管总局批准的唯一功能表述；
❌ 不能说"降血脂""调节血脂""治疗高血脂"等；
保健食品不是药物，不能代替药物治疗疾病。
```

**护栏把它拦了**，命中的是引号里的 `降血脂` 和 `治疗`。

**根因**：培训文档与合规话术里有大量**反例教学**（「❌ 不能说『降血脂』」），
纯正则会把这些引号里的禁用词当成违规命中。

**修法**：加「引述语境识别」，只放行**否定词 + 引号片段**：

```python
_QUOTED_NEGATION = re.compile(
    r"(?:不能说|禁止使用|错误说法|应改为|...)" 
    r"[^。！？\n]{0,12}?"
    r"(?:[「『\"'“”‘’][^」』\"'“”‘’\n]{1,24}[」』\"'“”‘’][、\s]*)+"
)
```

**放行边界（保守）**：

| 形式 | 处理 | 理由 |
|---|---|---|
| 否定词 + **引号** + 禁用词 | ✅ 放行 | 可靠的引述 |
| 「❌ 不能说：X」**整行到底** | ✅ 放行 | 独立反例行 |
| 「❌ 不能说：X，…」后面还有话 | ❌ 不放行 | 无法判断后半句 |
| 无引号的对照（`错误说法：降血脂`） | ❌ 不放行 | 与真违规文本无法区分 |

#### 修这个规则时踩的 3 个坑（都固化成测试了）

| 坑 | 后果 | 修法 |
|---|---|---|
| `[、，,\s]*` 把逗号吃进匹配 | 「不能说"X"，但我们这款确实X」后半句被漏检 | 引号间只允许顿号/空格 |
| 加 `等[^。！？\n]{0,10}` 收尾语 | 「等」后文字被吞，真违规漏检 | 去掉可选收尾语 |
| 挖整行而非挖局部 | 「❌ 不能说"X"，但确实X」整体放行 | 只挖引号片段 |

**最终验证：漏放 0 / 误拦 0**（20 个用例）。

### 问题 2：劝阻性表述被误拦

**现象**：`不可擅自停药或替代治疗` 被 `DC-01（治疗）` 拦。
这句恰恰是 **D005 要求的标准话术**。

**修法**：加 `_DISSUASION` 规则，放行「不可/不能 + 擅自/自行 + 停药/替代治疗」。

### 问题 3：否定性排除陈述被误拦

**现象**：`它不用于治疗高血脂症`、`不具有降血脂的治疗作用` 被拦。
这些是**最严谨的边界说明**。

**修法**：加 `_NEGATED_CLAIM` 规则，放行「不用于/不具备/不包括 + 功效词」。

**关键限制**：只放行**否定词与功效词紧邻**的形式。
`不能不说这个能降血脂` 不满足紧邻条件，仍被拦。

### 问题 4：BM25 索引从未构建

**现象**：端到端跑通，但「关键词命中=0」。日志里只有一行 warning。

**根因**：`Bm25SearchAdapter` 是纯内存索引，进程启动时是空的，没人调 `build_index`。

**后果**：P3 的三路融合实际只有两路在工作。

**修法**：装配根加 `_warmup_bm25()`，从 Milvus 读已入库的块建索引。
不从文件重建——避免与入库时的清洗规则产生偏差。

### 问题 5：★ BM25 噪声让「召回为空」防线失效（最隐蔽）

**现象**：问「你们有没有量子能量水」（库里完全没有），系统**编了答案**。

**根因排查**：

| 路 | 「量子能量水」的 Top1 |
|---|---|
| 向量 | **0.472**（低于 0.50 阈值，被正确拦下） |
| 关键词 | **11.74**（2-gram 命中「能量」「量水」等常见字组合） |

关键词路**没有分数阈值**，噪声命中把 `fused` 撑到 10，「召回为空」判定失败。

**这是 P3 验收记录里我写过的风险的实证**：
> 「向量永远返回 Top-N，判断召回为空必须靠分数阈值」
——当时只给向量加了阈值，漏了关键词。

**修法**：给关键词路加**双阈值**（实测标定）：

| 类型 | 关键词 Top1 范围 |
|---|---|
| 真实查询（12 条） | **15.60 ~ 28.48** |
| 噪声查询（8 条） | **5.15 ~ 11.86** |

- **绝对下限 14.0**：分界落在 12–15 之间，取 14 留余量
- **相对阈值 35%**：剪掉勉强沾边的长尾

**验证**：「量子能量水」现在 `fused=0 / llm_called=False / 96ms`。

> ★ 已知限制：BM25 分数与语料规模相关。语料大幅扩张后需重新校准
> （已做成构造参数 `min_keyword_score`）。

## 4. 一个设计决策：护栏拦截后重试而非放宽规则

**现象**：同一 prompt，两次调用输出不同（即使 `temperature=0`）：

| 第几次 | 输出 | 护栏 |
|---|---|---|
| 1 | 自己加了引号「"降血脂"」 | ✅ 通过 |
| 2 | 说「批准的唯一功能表述」 | ❌ 绝对化拦截 |

**这不是规则错，也不是模型的错**，是 LLM 输出的固有波动（服务端实现决定）。

**两个选择**：

| 方案 | 优点 | 缺点 |
|---|---|---|
| 放宽「唯一」规则 | 一次就过 | **真违规也会漏** |
| **护栏失败后重试一次** | 规则保持严格 | 多一次 LLM 调用（成本） |

**选了重试。** 理由：合规场景下，**漏放比多花一次调用贵得多**。

配置项 `guardrail_retries=1`。重试用尽仍被拦才转拒答。

## 5. 分区组装的两个改进

### 5.1 剔除参考资料里的错误示范

**问题**：`D006` 的「客户最常问的五个问题」里，Q1 同时给了：

```
错误示范：「能，很多人吃了血脂都降了」      ← 模型会学这个
正确示范：「批准的功能是『有助于维持血脂…』」
```

**实测**：模型确实被带偏，输出了「降血脂」。

**修法**：`_strip_bad_examples()` 按行剔除带 `❌/✗/×/错误示范/反例` 标记的行。

### 5.2 prompt 里明确标注

```
⚠️ 以下材料已剔除错误示范。写作时不要使用否认句（如「不能说X」），只做正面陈述。
```

**为什么加这句**：模型学会了「引用反例」这个模式后，会写出
「❌ 不能说降血脂」这样的句子——虽然合规，但读起来像在教违规。
明确要求「只做正面陈述」后，输出更像门店顾问。

### 6.3 ⚠️ P95 < 3s 部分未达标

实测 4 条查询：

| 查询 | 耗时 |
|---|---|
| 吃了能停降压药吗 | 2.73s |
| 在吃阿司匹林能吃鱼油吗 | 2.76s |
| 鱼油适合哪些人 | 4.14s |
| 鱼油有什么功能 | 4.97s |

**未达标项：P95 < 3s 未完全达成。**

**瓶颈在 LLM 生成**（3–5s，输出越长越慢），不在系统侧：
检索 118ms + 组装 <10ms + 护栏 <1ms，系统开销可忽略。

**可选优化（未做，需权衡）**：

| 方案 | 效果 | 代价 |
|---|---|---|
| 限制 `max_tokens` | 快 | 答案变简略 |
| 流式输出 | **感知延迟大降**（首字 0.5s） | 需要改接口为 SSE |
| 换更快的模型 | 快 | 质量可能下降 |
| 缓存常见问答 | 命中时 <100ms | 命中率不确定 |

**建议**：**上流式输出**。用户 0.5s 就能看到第一个字，体验远好于等 5s 看整段。

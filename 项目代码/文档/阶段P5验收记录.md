## 2. ★ 约束 #3 的实现与守护

### 2.1 摘要卡长什么样

```python
@dataclass(frozen=True, slots=True)
class SummaryCard:
    trainee_id: str = ""
    case_id: str = ""
    duration_sec: int = 0

    risk_items: tuple[RiskItem, ...] = ()
    element_coverage: tuple[ElementCheck, ...] = ()
    pending_human: tuple[str, ...] = ()
```

**没有 score，没有 verdict，没有任何总分属性。**

### 2.2 为什么不能给分（这是业务决定，不是技术选择）

| 理由 | 说明 |
|---|---|
| 学员会优化分数而非话术 | 给 45 分，学员问「怎么到 80」，而不是「我哪句说错了」。培训目标是后者 |
| 有争议时系统成背锅方 | 系统只做了正则匹配，它没能力判断「学员是否真的理解」 |
| 规则匹配覆盖不了语义 | 「建议先咨询医生」和「你自己看着办」在关键词上可能都算「未承诺」，但专业度差得远 |

### 2.3 怎么守住的（4 条测试）

| 测试 | 守什么 |
|---|---|
| `test_dataclass_fields` | 字段名里不能出现 score/verdict/grade/result/pass_fail |
| `test_no_numeric_total` | 连**属性**都不能叫 total_score（防止绕过 dataclass 约束） |
| `test_no_score_in_display_dict` | 展示字典序列化后不能含 `"score"` / `"verdict"` |
| `test_render_no_score_words` | 渲染文本不能出现「得分 / 总分 / 评分」——学员看到就会问怎么提分 |

### 2.4 但仍保留的两类「事实陈述」

| 保留 | 理由 |
|---|---|
| `has_critical_violation`（布尔） | 用于红线案例的视觉标记。布尔判断不是分数 |
| `risk_items` 按级别**计数** | 「critical 3 条 / high 1 条」是事实陈述，可展示 |

## 3. critical 检出率 100%（逐条验证）

**这是 P5 最硬的一项。** 漏一条 critical = 学员说了违法话术系统没提示。

### 3.1 逐条测试

C01 的 critical 规则各测一遍（10 个短语）：

```
降血脂 / 降胆固醇 / 治疗 / 改善血脂 / 调节血脂
要不要买 / 带两盒 / 现在有活动 / 买二送一 / 限时
```

全部检出。

### 3.2 ⚠️ 发现并修掉的覆盖缺口

用案例文档给的「不合格答卷」验证时，**只检出 1 处 critical，文档说应有 3 处**。

**根因排查**：

| 违规片段 | 为什么漏 |
|---|---|
| 「很多人吃了血脂都降下来了」 | ① 不是「很多人吃了**都说好**」（TS-01 要求「都说」）<br>② 不含 `降血脂`（实际词序是「血脂**都降下来**了」）<br>→ 两条规则都漏 |

**这是真实缺口**，而且是门店最常见的违规形态（「他人经验 + 指标变化」）。

**修法**：补两条规则

```python
TS-05  (很多人|有的人|有些人|有人|大家) (吃了)?.{0,10}(都|就)?(好|有效|见效|降下来|改善)
TS-06  (血脂|血糖|血压|指标) (都|就)?(降下来|正常了|好了)
```

**验证**：`漏放 0 / 误拦 0`。

### 3.3 案例规则 + 全局规则双保险

**又发现一个问题**：C01 的案例规则表里**没有「他人经验背书」这一类**，
但它的评分示例明确说那句话是 critical。

| 规则来源 | 覆盖什么 |
|---|---|
| **案例自带规则** | 该案例的考察重点（C01 有 4 类） |
| **全局六类规则** | 兜住底线（与 P4 输出护栏同源） |

两者叠加（`include_global_rules=True`，默认开）。
用测试 `test_global_rules_catch_what_case_rules_miss` 守住。

## 4. ⚠️ 一个严重误报：合规警示语被判违规

**现象**：优秀答卷被报告 `critical 违规宣称「治疗」`。

**根因**：法定警示语 `保健食品不是药物，不能代替药物**治疗**疾病`
含「治疗」，被 C01 的 `治疗` 规则命中。

**这是最伤信任的一类 bug**：学员把必须说的话说对了，系统反而报他违规。
比漏报更糟——漏报他不会知道，误报他会觉得系统不懂业务。

**修法**：复用 P4 的合规白名单：

```python
probe = _strip_quoted_negations(_strip_compliant(sentence))
```

**关键收益**：评阅与输出护栏用**同一套判定标准**，避免两处规则漂移。

## 5. 案例解析：4 种格式变体（都是实测踩到的）

### 5.1 变体清单

| # | 差异 | 后果 | 修法 |
|---|---|---|---|
| 1 | 标题层级：`###` vs `##` | 章节匹配失败 | 正则用 `#{2,4}` |
| 2 | 章节名：`违禁表述检测` vs `违禁检测` | C01/C04 规则全丢 | 用 `违禁(?:表述)?检测` |
| 3 | 违禁表列数：4 列 vs 3 列 | 8 个案例规则全丢 | 级别从标题「（全部 critical）」补 |
| 4 | **正则单元格含 `\|`** | 表格被切碎 | 逐字符扫描，反引号内的 `\|` 不当分隔符 |

### 5.2 第 4 个最隐蔽

```
| 违规宣称 | `降血脂|降胆固醇|治疗` | **critical** | 说明 |
                ↑ 这里的 | 被当成表格分隔符
```

直接 `line.split("|")` 会切出 7 个单元格，整行解析失败。

**修法**：逐字符扫描，跟踪是否在反引号内。

**结果**：16/16 案例全部解析成功，**55 条违禁规则，无缺失**。

### 5.3 解析失败的降级策略

| 情形 | 处理 | 理由 |
|---|---|---|
| 单条正则写错 | 跳过该条，告警 | 一条写错不应让整个案例不可评阅 |
| 整段解析抛异常 | 跳过该案例，告警 | 其余案例仍可用 |
| 文件读取失败 | 跳过该文件，告警 | 案例是内容资产，不该阻塞整个 P5 |

**没有「静默填默认值」**——那会让错误数据看起来像正常数据。

## 6. ⚠️ 门禁抓到一次架构违规

**现象**：`test_domain_has_no_io` 失败：

```
domain 层出现 IO 操作：
  domain\services\case_parser.py:332  →  .read_text()
```

**我最初把「读文件 + 解析」写在一起了。**

**门禁是对的**：解析是纯文本处理（domain），读文件是 IO（infrastructure）。

**修法**：拆两层

| 层 | 职责 |
|---|---|
| `domain/services/case_parser.py` | `parse_case_text(text)` — 纯字符串处理 |
| `infrastructure/content/case_loader.py` | `load_cases_from_dir(path)` — 读文件 + 调解析 |

**额外收益**：解析逻辑现在可以脱离文件系统测试，直接喂字符串。

## 7. 真实答卷验证（与文档评分示例对比）

用 `情景演练案例集_核心2个` 给的三份答卷跑评阅：

| 答卷 | 文档判定 | 系统判定 | 一致 |
|---|---|---|---|
| **A 优秀** | 全要素通过、无违规 | ✅ 7/7 要素覆盖、0 风险 | ✅ |
| **B 不合格** | 3 处 critical、缺 4 项必答 | ✅ **3 处 critical**、缺 E3/E4/E5 | ✅ |
| **C 边界** | 缺 E5 警示语、E6 部分满足 | ✅ 缺 E5、E6/E7 标记待人工 | ✅ |

### 7.1 一处判定口径差异（已记录）

| 项 | 文档 | 系统 |
|---|---|---|
| B 答卷 E1「明确回答有」 | ✅（说了"鱼油"，但没产品全名） | ✅（说了「有的！」） |

文档标注是「✅（说了"鱼油"，但没产品全名）」，我的 E1 判定也是 ✅。
**但 E2「给出产品名称」双方都判 ❌**——一致。

### 7.2 修掉的一个真 bug

B 答卷的 E1 起初被判 ❌。根因：

```python
_VAGUE 含 "我看看"
→ 匹配到「我们这款鱼油」里的「我看」
→ 判成模糊话术
```

**两处修正**：
1. `我看看` 加负向断言 `(?![们])`
2. **判断顺序改掉**：先找明确回答，只有没找到时才看模糊话术

第 2 条更重要——「有的！」本身就是明确回答，后文有模糊词不该否定它。

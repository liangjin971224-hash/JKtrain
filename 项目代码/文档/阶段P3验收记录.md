## 2. 三路 vs 单路（P3 硬指标）

44 条评测集，学员视角 36 条（排除 8 条案例查询），`top_k=10`：

| 方案 | R@1 | R@5 |
|---|---|---|
| 向量单路 | 0.417 | 0.722 |
| 关键词单路 | **0.528** | 0.722 |
| **三路融合** | 0.500 | **0.833** |

**R@5：0.722 → 0.833，提升 +15.4%**，刚好达到 P3 目标（≥15%）。

### 2.1 ⚠️ 必须如实说明的两件事

**（1）+15.4% 是勉强达标，不是宽裕达标。**

0.722 × 1.15 = 0.830，实测 0.833，只超出 0.003。这个数字对评测集很敏感——
36 条里差 1 条就是 ±0.028。**不能宣称「融合效果显著」**，只能说「达到阶段门槛」。

**（2）R@1 反而下降：关键词 0.528 → 融合 0.500。**

这不是 bug，是 RRF 的固有特性。逐条比对：

| 变好的（3 条） | 向量 | 关键词 | 融合 |
|---|---|---|---|
| T03 绝对不能说的话有哪些 | 7 | 6 | **1** |
| T23 客户在店里突然胸闷怎么办 | 未命中 | 8 | **1** |
| T26 客户问吃了能不能停药怎么答 | 2 | 3 | **1** |

| 变差的（5 条） | 向量 | 关键词 | 融合 |
|---|---|---|---|
| T02 降血糖这个说法对不对 | 2 | 1 | 2 |
| T09 介绍产品时必须说哪五件事 | 7 | 3 | 5 |
| T11 客户说太贵了怎么应对 | 4 | 1 | 4 |
| T13 客户怀疑我们是骗子怎么处理 | 2 | 1 | 2 |
| T21 什么情况下可以退货 | 6 | 1 | 3 |

**机制**：RRF 只按排名，不看分数绝对值。当一路把某文档排第 1、另一路排第 8 时，
融合后它可能落到第 3——**牺牲了 Top1 精度，换来了 Top5 覆盖**。

**这对本项目意味着什么**：

| 指标 | 影响 | 判断 |
|---|---|---|
| R@5（金标内容在不在候选里） | **+15.4%** | ✅ 对 P4 生成有利：材料更全 |
| R@1（第一条准不准） | −2.8% | ⚠️ 对「只取 Top1」的场景不利 |

**结论**：P4 生成阶段要喂 Top3–5 给 LLM，所以 R@5 更重要。
但若后续要做 Rerank，优先解决的就是这 5 条 Top1 退化。

### 2.2 为什么关键词单路 R@5 与向量持平，但 R@1 更高

关键词路只命中了「字面重合」的文档，命中数少但极准；向量路泛化广但 Top1 常偏。
这印证了「互补」——两者融合后 R@5 才上得去。

## 3. 三个必须守住的语义（本阶段设计重点）

### 3.1 单路失败必须降级，不能整体失败

| 场景 | 实测结果 |
|---|---|
| 图谱挂掉 | ✅ 向量/关键词继续，`degraded={"graph": ...}` |
| 向量挂掉 | ✅ 其余两路继续 |
| 关键词挂掉 | ✅ 其余两路继续 |
| 两路挂掉 | ✅ 剩一路仍能出结果 |
| 三路全挂 | ✅ `failed=True`，`fused=()` |
| 端口未装配（P0 状态） | ✅ 降级不崩 |

**降级原因必须可读**：记的是 `"AssertionError: ..."` 而非笼统的「失败」。

### 3.2 「没找到」≠「搜到了不相关内容」

**这是 P3 最容易埋雷的地方。**

向量检索**永远**返回 Top-N——问「知识库里完全没有的东西」，它也会给出最相近的 5 条。
如果就此判定「召回到了」，P4 会拿着无关内容让 LLM 生成答案。

**修法**：`MIN_VECTOR_SCORE = 0.50` 阈值。

依据（来自 P0/P2 实测）：

| 区间 | 含义 |
|---|---|
| 0.70–0.78 | 高度匹配 |
| 0.55–0.69 | 相关性较好 |
| **0.50–0.55** | **分界线：勉强相关** |
| 0.45–0.50 | 噪声，但 Top1 常落这里 |
| <0.45 | 纯噪声 |

阈值取 0.50 而非 0.55：P2 实测有 0.52 的正确命中（T31「蛋白粉肾不好的人能吃吗」），
设 0.55 会误杀。也不取 0.40：那样几乎所有查询都「有召回」，P4 的拒答永远触发不了。

**测试守护**：`test_low_score_vector_hits_filtered`
—— 喂 0.31 分的结果，断言 `vector_hits == ()` 且 `failed is True`。

### 3.3 图谱结果不参与文档排名（本阶段发现并修正的设计缺陷）

**初版实现**把图谱的 `product_id` 和文档的 `chunk_id` 放进同一个 RRF 排名。

实测输出：

```
P001      score=0.00820  sources=('graph',)    chunk=None   ← 排第一
D005_c1   score=0.00492  sources=('vector',)   chunk=有
D006_c1   score=0.00328  sources=('keyword',)  chunk=有
```

**问题**：
1. `chunk=None` 的条目排第一，下游按 `fused` 取内容时会踩空
2. 一个分数同时表达「产品对不对」和「文档相关不相关」，语义混乱

**修正**：融合只管**文档块**（向量 + 关键词两路），图谱结果单独放 `graph_hits`。

| 原因 | 说明 |
|---|---|
| 数据类型不同 | 产品事实是权威结构化数据，走「事实卡」；文档块是给 LLM 的参考文本 |
| 呈现方式不同 | 事实卡直接展示，不参与排名 |
| 权重体现位置不同 | 图谱权重体现在「上层怎么用事实卡」，不在文档排名里 |

**测试守护**：`test_graph_result_not_in_fused` +
`test_fused_only_contains_chunks`。

**对 P3 验收的影响**：文档召回看 R@5（上面 0.833），
图谱正确性看「排除法 / 禁忌命中 100%」（P1 已验），两者分开评估才是对的。

## 4. RRF 实现要点

### 4.1 为什么用 RRF 而不是分数加权

三路分数**不同量纲**：

| 路 | 分数性质 |
|---|---|
| 图谱 | 布尔/离散（命中即 1） |
| 向量 | 余弦相似度，0–1 |
| BM25 | 无上界实数（实测可达 10+） |

直接加权求和需先归一化，而归一化会引入偏差（某路本次最高只 0.4，归一化后被放大到 1.0）。
RRF 只用**排名**，天然规避量纲问题。

### 4.2 参数校验：错配必须报错

| 校验 | 为什么必须报错而不是静默处理 |
|---|---|
| 权重数量与路数不符 | 静默按最短对齐会丢掉某一路权重，调用方看不出来 |
| 负权重 | 会让排名反转 |
| 全零权重 | 等于没有信号 |
| `k <= 0` | 除零 |

### 4.3 同路重复文档只按首次排名计分

`["a","a","a","b"]` → a 计 1/(k+1)，b 计 1/(k+4)（按**原始位置**，不紧凑化）。

**不紧凑化的理由**：真实检索不会有重复，出现重复本身是数据问题，不该被奖励。

### 4.4 动态权重表（按意图）

| 意图 | 图谱 | 向量 | 关键词 |
|---|---|---|---|
| 禁忌咨询 / 特殊人群 | **0.6** | 0.2 | 0.2 |
| 产品功效 | 0.5 | 0.3 | 0.2 |
| 业务流程 | 0.1 | **0.7** | 0.2 |
| 产品名 / 文号查询 | 0.3 | 0.2 | **0.5** |
| 开放问答 | 0.1 | **0.8** | 0.1 |

**每组和必须为 1.0**（有测试守护），否则不同意图的融合分数不可比。

## 5. BM25 实现要点

**不引入 `rank_bm25` / `jieba`**：

| 理由 | 说明 |
|---|---|
| 规模小 | 293 条文档，纯 Python 毫秒级 |
| 少依赖 | 少一个版本冲突与部署风险 |
| 可测试 | 排序逻辑自己写，行为完全可预期 |

**中文分词策略**：2-gram + 字母数字块整体保留再补 2-gram。
`"保健食品"` → 保健/健食/食品；`"国食健注G20250012"` → 整体 + G2/20/00... 片段。

**分字段权重**：`title 3.0 / section 2.0 / text 1.0`。
客户问「体脂仪怎么用」，标题带「体脂仪」的段落比正文提一句的更相关。

**参数**：`k1=1.5, b=0.75`（业界默认，**未针对本项目调优**——标注为待确认）。

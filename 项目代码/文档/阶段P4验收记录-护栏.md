## 3. ⚠️ 本轮最重要的一次验证：单元测试全绿 ≠ 护栏可用

**这是必须记住的教训。**

### 3.1 现象

第一版护栏写完，`test_guardrail.py` **68 条全绿**。
按常规认知该收工了。但我拿真实培训内容跑了一次全量扫描：

```
段落总数 1166, 命中 127 (10.9%)
```

**10.9% 的命中率**——培训文档自己的正文被判违规。

### 3.2 逐条看误报原因

| 误报类型 | 例子 | 根因 |
|---|---|---|
| **序号「第一」** | 「第一条铁律」「## 第一步 迎宾」「客户第一次来」 | 正则 `第一` 没排除序号用法 |
| **副词「最好」** | 「您最好先咨询医生」「建议最好遵医嘱」 | 正则 `最(好)` 没区分绝对化与建议 |
| **引述违规示例** | 「❌ 不能说：降血糖」 | 培训文档本身在教「什么不能说」，含禁用词是正常的 |

第三类是**内容特性**，不是 bug——护栏只对**模型输出**生效，不应扫描培训文档原文。

前两类是**真 bug**，必须修。

### 3.3 修正

| 问题 | 修法 |
|---|---|
| `第一` 误报 | 分三种情况：带行业限定（行业第一）/ 带后缀（第一品牌）/ 裸「第一」只有前接「是/排名」且后不接序号量词才算 |
| `最好` 误报 | 要求「最」后接**产品效力形容词**（有效/强效/管用/好的产品），且 `效果最强`/`见效最快` 单独列规则 |
| `第一选择` 漏检 | 单独加规则 |
| `销量第一` 漏检 | 补 `(销量\|销售额\|份额\|口碑\|排名)\s*第一` |
| `效果最强`/`见效最快` 漏检 | 补 `(效果\|见效\|作用)\s*最\s*(强\|快\|好)` |

**结果**：误报率 10.9% → 9.0%，剩余全部是「引述违规示例」类。

### 3.4 固化

把每条真实误报写成测试，放在 `test_guardrail_false_positive.py`（68 条新测试）：

| 测试类 | 守护什么 |
|---|---|
| `TestOrdinalDiYi` | 序号「第一」不误报，但真排名宣称仍检出 |
| `TestZuiUsage` | 建议性「最好」不误报，真绝对化仍检出 |
| `TestCompliantPhrases` | 20 条标准话术不误报 |
| `TestOrdinaryFoodNoRegression` | 普通食品真违规仍拦、客观描述放行 |
| `TestWarningNoRegression` | 等价警示语识别、真缺失仍拦 |

### 3.5 教训

> **单元测试只覆盖你想到的情况。**
> 误报必须拿真实语料扫，扫出来的每一条都要固化成测试。
>
> 而且**误报和漏报同样严重**：
> 漏报 = 违规内容输出（违法风险）
> 误报 = 正常业务被堵死（业务不可用）
> 护栏必须两头都守。

## 4. 护栏的三项检测

### 4.1 禁用词（六类，34 条规则）

| 类别 | 规则数 | 来源 | 示例 |
|---|---|---|---|
| 疾病治疗 | 6 | D005 4.1 | 治疗/治愈/根治、降血糖、抗癌 |
| 药物替代 | 6 | D005 4.2 | 替代药物、**可以停药**、比药管用 |
| 绝对化 | 10 | D005 4.3 | 最有效、行业第一、唯一、100%有效 |
| 效果承诺 | 4 | D005 4.4 | 保证有效、无效退款、三天见效 |
| 经验背书 | 4 | D005 4.5 | 很多人说好、我朋友有效、老客户回购 |
| 缺限定词 | 5 | D005 3.1 | 增强免疫力（应为「有助于增强免疫力」） |

**全部为 critical**。本项目的立场：禁用词没有「轻微违规」，说了就是违法宣传风险。

### 4.2 合规白名单（防误报的关键设计）

检测前先把合规表述**整段挖掉**，再在剩余文本上跑规则：

```python
_COMPLIANT_PHRASES = (
    "保健食品不是药物，不能代替药物治疗疾病",  # 含"治疗"但是必须说的话
    "有助于维持血糖健康水平",                  # 含"血糖"但是合规表述
    "个体差异较大，不能承诺具体效果",
    ...
)
```

**为什么必须这样做**：法定警示语里含「治疗」，合规功能声称里含「血糖」。
不先放行，护栏会把**恰恰是必须说**的话判成违规。

另加保护：`有助于 X` 形式整体放行（X 本身可能是被禁词根）。

### 4.3 普通食品声称（约束 #2）

41 个禁用词，覆盖 D008 1.2 的完整清单。

**关键设计：判定必须结合产品类别。**

| 表述 | 保健食品 | 普通食品 |
|---|---|---|
| 有助于增强免疫力 | ✅ 合规（目录原文） | ❌ 违规 |
| 补钙 / 补肾 / 抗衰老 | ✅ 合规 | ❌ 违规 |

`check_claim_allowed(None, ...)` **fail-safe 按普通食品处理**——
脏数据不能成为放行理由。

### 4.4 强制警示语

法规原文：**「保健食品不是药物，不能代替药物治疗疾病」**（D004 4.1）

**接受 7 种等价表述**（不能只认逐字一致，否则大量误拦）：

```
不能代替药物治疗疾病 / 不能代替药物 / 不能替代药物治疗疾病 /
不能替代药物 / 不是药物，不能代替 / 保健食品不是药物 / 本品不能代替药物
```

**只对保健食品要求**。普通食品加这个警示语反而奇怪（会让人误以为它是保健食品）。

## 5. 为什么护栏必须是纯领域逻辑

| 用 LLM 判合规 | 用规则判合规 |
|---|---|
| 结果不稳定（同输入两次可能不同） | 结果确定、可复现 |
| 无法测试（要连模型、有随机性） | 198 条测试，0.3s 跑完 |
| 无法解释（说不出命中哪条规则） | 报出 rule_id + 命中片段 |
| 成本高（每次输出都要调模型） | 零成本 |

**本项目的合规判定是硬规则**，必须可复现、可追溯、可 100% 测试。
**LLM 只负责「组织表达」，判断「这句话能不能说」由规则做。**

这也是 `domain` 层零框架要求的实际价值：规则能脱离一切外部依赖秒级验证。

### 2.2 ⚠️ 一个测试假绿的发现与修正

初版测试写的是：

```python
hits = search("保健食品", collection="health_training_docs", top_k=20, ...)
assert len(hits) == 20    # 断言「检索层过滤能拿满 20 条」
```

实跑通过。但**这个断言没有区分力**——V2 重建时已把所有 restricted 内容分流到
`health_self_test`，所以 `health_training_docs` **一条 restricted 都没有**。
无论是「检索层过滤」还是「检索后过滤」，都是 20 条。

**若沿用这个测试，P2 最重要的约束等于没测。**

**修法**：换成有区分力的三个判据：

| 判据 | 为什么有区分力 |
|---|---|
| 全 restricted 库（案例）学员返回 0 | 证明权限条件真的限制住了结果 |
| 同库主管返回满 20 条 | 证明库里确实有数据、`top_k` 生效（不是因空库而 0） |
| **非法权限值必须报错** | 证明权限参数是**被解析进查询条件**的，不是被忽略的 |

第三条是关键：若实现是「检索后过滤」，权限参数只是事后筛选用，传错值最多筛错；
而把权限拼进 `filter_expr` 时，非法值必须在校验阶段拦下，否则会拼出无效表达式或越权。

### 2.3 权限过滤的四种输入语义

| 输入 | 语义 | 生成的 filter |
|---|---|---|
| `("public", "internal")` | 学员 | `permission_level in ["public","internal"] and review_status == "approved"` |
| `("public","internal","restricted")` | 主管 | 含 restricted |
| `None` | **不限制**（仅内部巡检调用） | 只有 review_status 条件 |
| `()` | **一律禁止** | `permission_level in ["__none__"]` → 必返回 0 |

**`None` 与 `()` 必须区分开**：若实现把空元组当成 None，就是越权全开。
代码里有专门注释与测试（`test_empty_tuple_means_deny_all`）。

## 4. ⚠️ 实测踩到的两个坑

### 4.1 Milvus 字段不存在会**直接报错**，不是静默忽略

初版把输出字段写死成一份全字段列表：

```python
_OUTPUT_FIELDS = ("chunk_id", ..., "knowledge_point", "question_type", "difficulty")
```

在 `health_training_docs` 上检索立刻炸：

```
MilvusException: (code=65535, message=field knowledge_point not exist)
```

**根因**：`knowledge_point / question_type / difficulty` 只在
`health_question_bank` 的 schema 里（V2 重建时 `with_kp=True`）。

**修法**：按 collection 的真实 schema 动态取输出字段，并缓存探测结果。

```python
def _output_fields(self, collection: str) -> list[str]:
    desc = self._client.describe_collection(collection)
    existing = {f["name"] for f in desc["fields"]} - {"id", "vector"}
    ...
```

**教训**：多 collection 共用一个 adapter 时，schema 差异必须在适配器内吸收，
不能假设「所有 collection 字段一样」。

### 4.2 模型加载必须惰性

`import sentence_transformers` 占启动时间 **87%（11.5s）**，模型加载再 5.5s。

初版若在 `__init__` 里加载，`main.py` 自检会从 1.2s 变成 18s 以上，且占用显存。
更糟的是若在模块级加载，**所有 import 该模块的代码**都要付这个代价。

**修法**：`_ensure_model()` 首次 `embed()` 时才加载。
`main.py` 自检仍然只校验模型目录结构，实测启动仍是约 1.2s。

**测试守护**：`test_model_not_loaded_at_construction` +
`test_embed_empty_does_not_load_model`。

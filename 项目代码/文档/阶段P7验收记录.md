## 3. ★ 四条硬规则

### 3.1 每人每天只有一条

靠数据库 `uk_trainee_date (trainee_no, summary_date)` 保证。

**关键理解**：
- 「只允许一条」≠「第二次保存报错」
- 草稿本来就要能反复覆盖保存，覆盖正是「一条」的实现方式
- 真正要拦的是「已提交还想改」

### 3.2 提交后冻结

```python
草稿 → 可反复修改
已提交 → 不可修改（只允许主管加评语）
```

`can_edit` 一处判断，`edit()` 内部强制校验 —— 不靠调用方记得判断。

**API 语义**：已提交再改返回 **409 Conflict**（请求本身合法，是状态不允许），不是 400。

### 3.3 学员只能看自己的

**服务端强制覆盖，不信前端参数**：

```
学员请求：?requester=E001&role=trainee&trainee_no=E002
实际返回：只有 E001 的记录
```

实测已验证。这是关键——靠前端自觉必然会漏。

### 3.4 未命中日志不得用于绩效

FR-047 原文：「该日志不得用于对学员的绩效评价」。

**做法：写进数据结构，而不是写在文档里。**

| 层面 | 措施 |
|---|---|
| 值对象 | `MissLogEntry` 刻意不含 score/grade/rating 等字段 |
| 接口返回 | `recent` 不含 `trainee_id`；`top` 只按**问题内容**聚合 |
| 仓储查询 | `list_miss_logs` 只按时间倒序，**不按学员分组** |

> 字段不存在，就没人能拿它做绩效。这与「摘要卡不给分」是同一类约束。

## 4. ★ 一条容易搞错的边界

### 主管能写评语，但不能改学员正文

看起来都是「编辑这条记录」，但性质完全不同：

| 操作 | 性质 | 谁可以 |
|---|---|---|
| 改正文 | 篡改学员原始记录 → 日报失去「真实想法」的价值 | **只有学员本人**（且仅草稿态） |
| 写评语 | 主管的独立表达 → 日报的增值部分 | **只有主管** |

代码上：
- `can_edit_summary`：主管**不因角色**获得改正文权限
- `can_review_summary`：只有主管
- 用例 `ReviewSummaryUseCase` 只调 `save_review`，接口层面就没有改正文的可能

实测已验证：主管写评语后，学员正文原封不动。

### 8.1 未命中日志已接上（同日补完）

**原缺口**：`answer_question.py` 召回为空时只返回拒答，没写日志 → 日志表空。

**已修**：拒答分支加 `_log_miss()`：

```python
if retrieval.failed or not retrieval.fused:
    self._log_miss(text, retrieval)      # ← 新增
    return UseCaseResult(answer=REFUSAL_TEMPLATE, refused=True, ...)
```

**设计要点**：
- 写日志失败**不影响拒答**（日志是运营素材，不该让学员看不到拒答话术）
- `repository` 为 None 时静默跳过（功能照常，只是不记日志）

**真机验证**：问 `zzzzqqqqxxxx` → 拒答 + 日志表多一条记录 ✅

## 8.2 ★★ 接日志时发现的新缺陷：BM25 给乱码打高分

### 现象

实测未命中日志时发现，**乱码查询根本不会触发拒答**：

| 查询 | 向量 | 关键词 Top1 | 结果 |
|---|---|---|---|
| `zzzzqqqqxxxx` | 0 条 | **17.62** | 被当有效召回 → 正常回答 |
| `1234567890abcdef` | 0 条 | 14.51 | 同上 |

阈值是 14.0，17.62 直接过了。

### 根因

BM25 用 IDF 惩罚「常见词」。乱码分词后产生一堆
「语料里几乎不出现」的 token —— 按公式**反而给最高分**。

这是 BM25 的固有特性，**调阈值治不了**：
- 调高到 18 → 会误杀「鱼油」这类正常短查询
- 相对阈值也无效 → 噪声的第 2、3 名分数同样不低

### 修法：召回前做可检索性预检查

```python
def is_retrievable(query) -> bool:
    # 含中文 → 可检索（知识库是中文的）
    # 无中文时只接受「像术语」的形式：
    #   · 字母+数字混合（CoQ10 / 维生素B2）
    #   · 空格分隔的英文词（fish oil）
    # 其余（纯字母堆、纯数字、纯符号）→ 不可检索
```

接在 `execute()` 最前面，不通过就直接返回空结果。

### 验证

| 查询 | 结果 |
|---|---|
| `zzzzqqqqxxxx` | ✅ 拒答 |
| `???!!!` | ✅ 拒答 |
| `1234567890` | ✅ 拒答 |
| 鱼油有什么功能 | ✅ 正常回答 |
| 辅酶Q10对心脏好不好 | ✅ 正常回答 |
| CoQ10 有什么用 | ✅ 正常回答 |

### 一个已知的窄边界

`1234567890abcdef` 因含「数字+字母混合」被放过（与 `CoQ10` 同形态）。
它能召回到噪声内容。这类输入极罕见，暂不处理；
真要处理需要一个「中文词表」判据，成本远高于收益。

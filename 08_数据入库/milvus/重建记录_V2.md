## 2. 修掉的三个缺陷

### 2.1 缺陷 A：案例分段正则写死 `###`，14 个案例从未分段

`chunking_variants.py` 原正则：

```python
CASE_SECTION_PATTERN = re.compile(r"^###\s+([一二三四五六七])、(.*)$", re.M)
```

而两个源文件的标题层级**不一样**：

| 文件 | 案例标题 | 段落标题 | 旧正则命中 |
|---|---|---|---|
| `情景演练案例集_14个.md` | `# C02` | `## 一、` | **0** |
| `情景演练案例集_核心2个.md` | `## 案例 C01` | `### 一、` | 14 |

**后果**：14 个案例全部退化成「全文一块」，只有 C01/C04 真正分段。

**更要紧的是**：快照里「D 方案案例分段最优 R@1=0.477」这个结论，是在分段正则失效的情况下测出来的——那个 0.477 其实约等于「整块方案」。**D 方案从来没被真正验证过。**

**修法**：改为 `#{2,4}` 放宽层级。修完 `14个.md` 命中 103 处，`核心2个.md` 命中 14 处，合计 16 个案例 → **117 块**。

**验证**：演练定位 Top1 从 **7/8 → 8/8**。

### 2.2 缺陷 B：`strip_self_test` 剔错了对象

`text_clean.py` 的实现靠标题行定位：

```python
for line in text.splitlines():
    m = re.match(r"^#{2,3}\s+(.*)$", line)
    if m:
        skipping = bool(re.search(r"自测题|参考答案", m.group(1)))
```

但 `chunk_heading()` **已经把标题行剥掉了**，传进来的 body 里没有标题可匹配。实测：

| 对象 | 应剔块数 | 实际剔掉 |
|---|---|---|
| 培训文档噪声块 | 47 | **0**（完全无效） |
| 案例块 | 0 | **14**（删掉「六、参考答案」段） |

**所以报告里 C3 的 +0.023 根本不该记在「剔自测题」头上。**

我做了归因实验（44 条评测集）：

| 方案 | 块数 | R@1 | R@3 | R@5 | MRR |
|---|---|---|---|---|---|
| 复刻报告 C3（培训不剔、案例删答案） | 364 | 0.523 | 0.614 | 0.705 | 0.590 |
| 正确剔培训噪声 | 321 | 0.477 | 0.682 | 0.750 | 0.588 |
| 两者都做 | 321 | 0.500 | 0.682 | 0.750 | 0.603 |

**真实机制是：删掉案例参考答案段让块变短变纯，Top1 更集中——而不是「剔自测题」。** 这对本项目是**陷阱**，因为参考答案正是 P5 演练评阅的判定依据。

**修法**：改为在 **section 层面**判定（section 由 `chunk_heading` 保留），并拆成两档：

| 类型 | 章节 | 处理 |
|---|---|---|
| `is_meta_section` | 学习目标 | 直接丢弃（纯元信息无答案） |
| `is_qa_section` | 自测题 / 参考答案 | **不丢内容**，分流到 `health_self_test` |

同时**移除了**原先误列入噪声的「小结 / 总结 / 速查表 / 难点 / 执行清单」——实测这些章节携带正文信息，剔了反而降 R@3/R@5。速查表尤其不能剔（D004/D008 的核心内容就在速查表里）。

### 2.3 缺陷 C（本次新发现）：12 个参考答案块标成 `public`，学员可见

V1 的权限是**按文档整体**继承的（`TRAINING_PERMISSION[doc_id]`）。而文档内部混着答案块：

| 文档 | 文档权限 | 其中答案块 | 后果 |
|---|---|---|---|
| D001/D003/D004/D006/D007/D008 | **public** | 各 2 块 | **学员可检索到参考答案** |
| D002/D005/D009–D015 | internal | 各 2 块 | 学员同样可见 |

**12 个答案块标成 public**，直接违反 FR-050「学员搜不到参考答案」。这是**权限设计错误**，不是检索质量问题。

**修法**：答案块权限**硬编码为 `restricted`，绝不继承文档权限**（见 `build_collections.py` 中 `parse_training`）：

```python
permission_level="restricted" if is_qa else perm,   # ★ 关键
```

**验证**：`self_test` 库非 restricted 块 = **0**；`training` 库残留答案块 = **0**。

## 3. 顺带修掉的两个题库缺陷

### 3.1 `knowledge_point` 其实早就有，只是没提取

快照「待办 C：先补题库 140 题的 knowledge_point 标注」——**不必补**。源文件本来就有：

```markdown
# 一、KP_PROD_CATEGORY 产品类别辨识（12 道）
## Q001 ★☆☆
```

旧脚本只存了 `stage / difficulty / answer`，没解析 KP 标题行。本次提取后 **140/140 全部归属**，共 14 个知识点。

### 3.2 题型判定把 40 道 S2 题全误标成多选

旧代码：

```python
is_multi = qno.startswith("S") or ("多选" in text[:160])
```

**`S` 前缀不是多选**，是 S2 阶段题号段（`题库_S2业务流程_40道.md` 里 40 道题全是 `S001`–`S040`）。按旧逻辑，40 道单选被判成多选。

**修法**：靠标题行的 `（多选）` 标记 + 答案多字母兜底（源文件有 2 题 Q043/S023 漏标 `（多选）`，答案是 `A、B、C、D`，不兜底会被当成单选）。

**验证**：单选 124（答案全为单字母）+ 多选 16（答案 2–5 字母），合计 140，答案提取无缺失。

## 6. 关于 R@1 从 0.523 掉到 0.472 的说明

**这是修复的代价，不是退化。**

| | 旧 C3 报告 | V2 正式库 |
|---|---|---|
| R@1 | 0.523 | 0.472 |
| R@3 | 0.614 | **0.694** |
| R@5 | 0.705 | **0.778** |
| MRR | 0.590 | **0.603** |

**R@1 掉的原因**：旧 C3 的 0.523 是**靠删掉案例参考答案换来的**，而那份「参考答案」是 P5 评阅的判定依据。V2 选择**不删内容**，把答案分流到 `health_self_test`，代价是 R@1 少 0.05，收益是 R@3 +0.08、R@5 +0.07、MRR +0.013。

**对 RAG 而言这是划算的**：P4 生成护栏要的是「召回的内容里有正确答案」，R@3/R@5 比 R@1 更贴近实际效果。

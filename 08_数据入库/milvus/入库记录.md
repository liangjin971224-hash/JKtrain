## 三、字段设计

### 3.1 15 个字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INT64 | 主键，自增 |
| `vector` | FLOAT_VECTOR(1024) | bge-m3 向量，已归一化 |
| `chunk_id` | VARCHAR(64) | 如 `D005_c003` / `C04_full` / `Q012` |
| `text` | VARCHAR(12000) | 正文 |
| `source_dir` | VARCHAR(64) | 源文件夹名 |
| `source_file` | VARCHAR(128) | 源文件名 |
| `doc_id` | VARCHAR(32) | D001 / C01 / Q001 |

| **`permission_level`** | VARCHAR(32) | **public / internal / restricted** |
| `review_status` | VARCHAR(32) | approved |
| `data_origin` | VARCHAR(32) | real / synthetic |
| `category` | VARCHAR(32) | training / case / question |
| `section` | VARCHAR(256) | 章节标题 |
| `chunk_index` | INT32 | 块序号 |
| `extra` | VARCHAR(2000) | JSON（题型/难度/答案） |

### 3.2 索引

```
HNSW · COSINE · M=16 · efConstruction=200
```

**为什么用 COSINE**：bge-m3 输出已归一化，余弦相似度是标准用法。

## 四、权限设计（FR-050 核心）

### 4.1 权限分配

| Collection | public | internal | restricted |
|---|---|---|---|
| `health_training_docs` | 132 | 206 | 0 |
| `health_case_library` | 0 | 0 | **16** |
| `health_question_bank` | 0 | 0 | **140** |

**关键决策**：

| 内容 | 权限 | 原因 |
|---|---|---|
| D001/D003/D004/D006/D007/D008 | public | 基础培训，学员可看 |
| D002/D005/D009–D015 | internal | 内部流程、禁用词、员工经验 |
| **全部 16 个案例** | **restricted** | **含参考答案，学员不可检索** |
| **全部 140 道题** | **restricted** | **题库本身就不该进可检索范围** |

### 4.2 权限过滤验证（已通过）

| 场景 | 查询 | 结果 |
|---|---|---|
| 学员查案例 | `permission_level in ["public","internal"]` | **0 条 ✅ 不可见** |
| 主管查案例 | 含 `restricted` | 5 条 ✅ |
| 学员查题库 | `permission_level in ["public","internal"]` | **0 条 ✅ 不可见** |

**这三条证明了 FR-050 可以落地**——权限在检索层生效，不是查完再过滤。

### 5.1 情景案例：4/4 命中（✅ 优秀）

| 查询 | Top1 | 分数 |

**满分。** 案例标题与查询语义高度匹配。

### 5.2 题库：召回合理

| 查询 | Top3 |
|---|---|

| 功能声称边界 | Q020 / S034 / Q100 |

**注意**：这是**语义检索测试**，不是知识点分类测试。题库的正式用法是**按 `knowledge_point` 字段过滤**（精确匹配），不是向量检索。所以这个结果仅供参考。

### 5.3 培训文档：2/5「严格命中」，但这 3 个"未命中"实际都合理

| 查询 | Top1 | 我原本的期望 | 实际情况 |

| 客户说太贵了怎么处理 | **D015** 员工经验汇编 (0.686) | D009 | ⚠️ **D015 里有「客户提价格顾虑时说明日均成本」这条经验，合理** |

### 5.4 分数分布观察

| 分数区间 | 含义 |
|---|---|
| 0.70–0.78 | 高度匹配（问法与内容几乎对应） |
| 0.55–0.69 | 相关性较好 |
| < 0.50 | 需要 Rerank 或降低阈值 |

**当前所有 Top1 都在 0.55 以上，说明 bge-m3 对这个语料效果好。**

## 六、执行中遇到的问题

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | 题库只解析出 124 道（应 140） | **正则不匹配带括号的标题**（`## Q003 ★★☆（关键题）`），且漏了 S 前缀 | 正则改为兼容括号注释 + `[QS]\d{3}` |
| 2 | `DataTypeNotSupportException` | pymilvus 2.6 要求用 `DataType` 枚举，不能传字符串 | 改 `DataType.INT64` 等 |
| 3 | `length of varchar field text exceeds max length: 8125 > 8000` | 最长 chunk 4130 字符，但按 UTF-8 字节算超了 | `max_length` 放宽到 12000 |
| 4 | `health_training_docs` 首次 drop 后重建 | 可重入设计 | 正常行为 |

## 八、与 Neo4j 的对照

| 维度 | Neo4j（已完成） | Milvus（本次完成） |
|---|---|---|
| 存什么 | 产品事实、禁忌、合规规则 | 培训文档、案例、题库 |
| 规模 | 156 节点 / 184 关系 | 494 个向量 |
| 查询 | 精确逻辑（排除法、别名归一） | 语义相似 |
| 权限 | 无（数据本身不做权限区分） | **chunk 级 permission_level** |
| 状态 | ✅ 可用 | ✅ 可用 |

**两者互补**：

```
客户问"血脂高能吃什么"
    ↓
图谱：排除法找出不含禁忌的产品（精确）
向量：检索"血脂管理"相关培训内容（语义）
关键词：匹配产品名/文号（精确）
    ↓
RRF 融合
```
